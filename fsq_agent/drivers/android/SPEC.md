# Module: drivers.android

## Purpose

Implement Android automation through the `appium-connect-agent` `Runtime` and `Automation` public contracts (`appium_connect_agent` backend), including lazy thread-affine managed Appium server and Automation session lifecycle, declared actions, screenshot and compact `<hierarchy>` XML UI observation, device context, and backend failure normalization.

## Dependencies

- `core.interfaces.AndroidDriverInterface`, `capabilities`, and Android parameter/result models.
- Optional `appium-connect-agent` (`appium_connect_agent.contracts`, `appium_connect_agent.runtime`, `appium_connect_agent.automation`), imported lazily at runtime without private WebDriver access.

## Public Interface

Instances satisfy `AndroidDriverInterface`; the concrete backend class is private outside Drivers and composition.

`input_text` retains the existing target-or-locator parameter contract and replacement semantics. It establishes that the resolved target is an editable text control before clicking, clearing, or writing. Target existence, clickability, focusability, or focus alone is not sufficient; keyboard containers and other non-editable targets are rejected without text-entry side effects.

Successful text entry requires a bounded read-only postcondition check of the original target after replacement. Missing ids, whitespace-only ids, and the trimmed `"null"` sentinel are not resource identities. Before any click or write, a real nonempty raw resource-id is bound through public `Session.element("id", ...)` and checked for unique resolution and matching original type, package, id, and bounds. Standard fully qualified `package:id/name` values use exact native id matching without enabling raw-id Settings changes; nonstandard observed ids use the SDK's public `raw_id=True` guard to prevent autocomplete from changing their meaning. Post-write inspection re-resolves through that bound identity instead of the original mutable text or positional locator, preserves type/package/id, and permits bounds movement only for this proven identity. Original compound locator constraints govern initial target selection; binding never selects an arbitrary duplicate-id target.

Without a real resource-id, an initially unique text-independent locator is used directly for click, replacement, and post-inspection. An initially unique text-dependent locator is rebound before mutation through an exact XPath conjunction of the observed class, package, and Android bounds rectangle; a binding inspection must uniquely resolve and match the original identity and bounds before the bound element is clicked or written. Both no-id paths require unchanged type/package/bounds, no newly observed real id, enabled state, readable unmasked text, and verified replacement readback. Missing, ambiguous, or changed geometry is `verification_unavailable`, never success; post-entry re-anchoring failures explicitly state that text entry was sent and UI state must be inspected before re-entering, without claiming an unobserved bounds shift as fact. Ordinary input requires exact requested text, including empty strings and Unicode. A non-throwing backend call is not acceptance; no arbitrary write replay, alternative target, or focus-only untargeted keyboard fallback is permitted. The controlled numeric recovery below is the sole clear-and-keycode exception.

`input_text` pre-entry inspection requests `("type", "id", "package", "enabled", "displayed", "password", "text", "bounds")` to establish editability, visibility, readability, and target identity. Post-entry verification requests only `("type", "id", "package", "enabled", "password", "text", "bounds")`; it does not request the unused `displayed` attribute. Resource-id and geometric binding inspections request only `("type", "id", "package", "bounds")`. Enabled-state, unmasked-readability, and exact-text postconditions are required independently of the chosen binding.

Each `input_text` pre-entry, stable-id binding, and post-entry `Element.inspect` call uses `OperationControl(timeout_seconds=DEFAULT_OPERATION_TIMEOUT_SECONDS)` with the default operation budget of 25.0 seconds. This per-inspection budget does not change target-not-found semantic polling, click/write budgets, selected attributes, exact readback, cancellation, failure normalization, or Session quarantine. `assert_state`, visibility assertions, and public `inspect_element` retain their separate existing budgets; an operation timeout is not retried as a business action and never triggers implicit Session reconstruction.

Controlled numeric recovery is entered at most once, only when the bound element's `replace_element_value` raises the SDK public `CommandError` with `code="command_failed"` and `request_state="response_received"`, and the requested string is empty or contains only ASCII `0-9`, `-`, and `.`. Click failures, other error types/codes, absent request-state, `not_sent`, `response_unknown`, and other characters do not enter recovery. These public error fields do not independently identify an `ACTION_SET_PROGRESS` rejection or a WebView spinbutton; raw backend error messages are not parsed. The driver never repeats replacement, clear, or an already attempted key, and never reconstructs a Session for recovery.

Recovery retains the already bound element. Before clear, it re-inspects and verifies the original type/package/normalized id, readable unmasked text, and enabled state, with unchanged bounds required when there is no real id. It invokes public `Element.clear(wait_timeout_seconds=5.0, control=OperationControl(timeout_seconds=15.0))` once. All recovery inspections request exactly `("type", "id", "package", "enabled", "focused", "password", "text", "bounds")` with the default 25-second read-only operation budget. After clear, the same safety rules hold and its readable text is the in-memory baseline, not a separately observed DOM placeholder attribute. If `focused` is not explicitly True, exactly one click with the existing input-click budgets is followed by read-only focus polling. A monotonic 2.0-second window limits the start of further poll reads, with `DEFAULT_POLL_INTERVAL_SECONDS` (0.25 seconds) pauses capped by remaining window time. It does not shorten any inspection's operation control or cancel an in-flight read: a read started within the window may finish under its normal budget, so total elapsed time can exceed 2.0 seconds. Every poll must preserve target identity/safety and exact baseline text; either violation aborts immediately without keycodes. A safely completed poll with `focused=True` permits immediate key dispatch, including an in-flight read completing after the start window; otherwise expiry prevents further reads and returns the existing `numeric_focus` / `verification_unavailable` result. No click, clear, replacement, or attempted key is repeated; cancellation, quarantine and unknown-acceptance diagnostics are preserved.

After the post-clear identity and focus check (and its optional bounded refocus polling), characters are dispatched consecutively without per-character inspections or refocusing; the standard post-inspection verifies the result. Character mapping is exact: digits map to Android keycodes 7 through 16, `-` to 69, and `.` to 56; each character is sent once through public `Device.press_keycode` with a 10-second control. Empty input clears and verifies without keycodes. Inspections and key dispatch are separate non-atomic operations, not a claim of focus locking or continuous focus observation. Any partial clear/key failure retains safe diagnostics, cancellation, and unknown-acceptance semantics and instructs callers to inspect UI state before re-entry.

Post-verification still uses the bound element and standard post-inspection attributes and identity/enabled/readability rules. Only a completed controlled recovery may accept either exact requested text or the Chromium accessibility composition `requested + ", " + cleared_baseline` when both strings are nonempty; an empty request accepts only empty text or that exact baseline. No baseline is used after a successful ordinary replacement. No prefix, substring, whitespace, phone-number, locale, or general numeric-format equivalence is accepted. Placeholder baselines, input text, and observed text are never emitted in results or diagnostics. Recovery stages `numeric_clear`, `numeric_focus`, and `numeric_keycode` distinguish safe failures; unverifiable target/focus is `verification_unavailable`, rejected/unverifiable operations are non-success, and final readable text mismatch remains `entry_mismatch`.

`assert_state` (`assert`) requests only the attributes required by its active assertion branch, without changing its public parameters, text-predicate precedence, target-uniqueness checks, or result semantics:

- The text-assertion branch requests only `("text",)`, including when an element also supplies state predicates; the existing text branch retains precedence and the driver does not add state assertions that branch does not evaluate.
- A state-only assertion requests exactly the explicitly supplied boolean state fields, including expected `False`, once each in canonical order `("enabled", "checked", "selected", "clickable", "focused")`. Unasserted fields are not requested.
- A locator-only existence assertion requests only `("enabled",)` as the single observation needed to use the SDK's non-empty inspection contract. Its success requires unique target resolution, not an enabled value of `True`; this does not turn existence into an enabled-state or visibility assertion.
- `assert_visible` and `assert_not_visible` request only `("displayed",)` and retain their existing visibility, absence, and ambiguity semantics.

The reduced `assert_state` inspection retains `OperationControl(timeout_seconds=10.0)` and the existing semantic-wait and cancellation behavior. Its existing target-not-found semantic polling is preserved; operation timeouts and response-unknown failures remain operational non-successes, without business retry, implicit reconnection, or timeout expansion. Visibility assertions retain their existing polling policies. Attribute selection does not change initial idle policy, SDK-internal attribute dependencies, evidence capture, reports, or cleanup.

Locators use only the supported SDK `Session.element` strategies `id`, `accessibility id`, and `xpath`. `locator.resourceId` is stripped of leading/trailing whitespace before resolution; other string fields retain their existing exact semantics. Standard fully qualified `package:id/name` inputs use exact native id matching. A bare local resource-id uses one XPath matching the exact bare value or the fully qualified form constructed from each candidate node's own `@package`, independent of the Session target or driver app-id; this covers native nodes in other application and SystemUI windows. These XPath paths do not change id-autocompletion Settings and reject multiple matches rather than selecting one. Other nonstandard single ids retain exact `raw_id=True` matching; a single accessibility-id retains its native strategy. Compound string fields remain conjunctive and use the same resource-id normalization and per-node package rule as single-field resolution. Expected boolean states are assertion predicates, not locator predicates. The driver neither emits unsupported `-android uiautomator` or `class name` strategies nor drops compound constraints to choose a faster but different target.

`ui_snapshot` (`uiTree`) consumes public `Session.observe_tree()` `TreeObservation` and deterministically synthesizes compact Android `<hierarchy>` XML in `{"xml": ..., "coverage": ..., "compaction": ...}`. It preserves observed id values verbatim as `resource-id`, including SDK-localized native ids and bare WebView/nonstandard ids, without inventing a package prefix. Emitted ids round-trip through shared locator resolution under unchanged UI state and unique target resolution; ambiguous bare/native collisions remain explicit failures. It preserves `content-desc`, `text`, `class`, `package`, `bounds`, `window-id`, and non-default boolean states (`enabled="false"`, `displayed="false"`, `focused="true"`, `checked="true"`, `selected="true"`), folds meaningless layout-only wrapper nodes, clips `text` and `content-desc` to the first 50 characters, and falls back safely to complete unfolded `TreeObservation` XML serialization with the same id policy on unexpected compaction errors without accessing any private `_driver` handle.

`inspect_element` (`inspectElement`) is a driver-owned observation-kind capability using public `Element.inspect` for one uniquely resolved target and only the explicitly selected safe attributes. It preserves full `text` and `desc`, without the compact snapshot's 50-character clipping, and returns each requested attribute's explicit observation state and serializable value; bounds are represented by integer `x`, `y`, `width`, and `height`. Default attributes are `text` and `desc`; the fixed whitelist is Models-owned. A text request requires a prior public password observation explicitly equal to False; protected or unknown-password text is unavailable and is never read into or serialized as output. Unknown and not-applicable booleans are not invented as False. The existing runtime output-budget/artifact path retains complete safe values when an output is too large to remain inline. The operation retains a bounded 10-second control, normalized safe failures, cancellation, unique resolution, and observation recording policy; it neither changes UI state nor invokes a provider.

`inspect_with_ai` (`inspectWithAI`) is a driver-owned read-only observation with `driver_method="inspect_with_ai"`, `step_kind="observation"`, and parameters `prompt`, `mode="extract"|"locate"`, optional half-open image `region`, and `max_candidates=5`. It invokes public `session.device.inspect_with_ai(prompt, provider=..., mode=..., region=..., max_candidates=..., control=...)` on the Session owner worker. The SDK obtains one current screenshot and physical display size, validates candidate geometry/cardinality, and maps full-image bounds into physical pointer bounds/centers. FSQ never guesses mapping, reuses historical coordinates, implicitly clicks/swipes, or adds a second screenshot. Extract returns a summary without executable candidates; locate returns label/image_bounds/pointer_bounds/pointer_center/confidence with SDK image/pointer dimensions and PNG digest. Empty locate candidates mean no visual match, not assertion success or permission to guess a point.

The host reuses existing `visual_assertion_policy_resolver(context, capture_sequence)` and `AndroidVisualAssertionPolicy` for each inspection; no second resolver or shared-settings mutation exists. Missing/incompatible resolver authorization, sensitive/unknown frames, or unavailable model service fail closed before screenshot persistence/upload. The provider adapter validates the actual SDK callback PNG and budgets, writes that same authorized frame through the Run artifact store, then invokes the injected neutral visual model service at most once. It supplies the complete original image with the selected region identified; model image bounds remain full-image coordinates. Result and evidence refer to the same digest, and artifact failure prevents upload. No cached frame/policy survives invocation completion. Cancellation/deadline/quarantine and primary-versus-cleanup failure semantics remain intact.

Operational/privacy/provider/output/mapping failures produce a safe non-success observation with a machine-readable reason such as `privacy_blocked`, never assertion failure, fabricated candidates, or fallback mapping. Authorized screenshot references remain traceable if later processing fails. Diagnostics exclude raw exception messages, image bytes, credentials and hidden reasoning. Existing deterministic assertions and `assert_with_ai` are unaffected.

`assert_with_ai` / `assertWithAI` remains the sole appearance/image/map/canvas assertion capability, not a visual locator or driving tool. Its Models-owned assertion parameters, exact accessible-state preference, structured deterministic-conflict adjudication, tri-state outcomes, capture policy, and inability to return driving coordinates remain unchanged. The separate observation capability does not broaden assertion semantics.

Before screenshot persistence or provider upload, the host requires explicit upload permission and an independently trusted current-frame non-sensitive decision. Public SDK inspection can establish an individual element's password observation, not frame-wide pixel coverage. Known password content, unknown sensitivity, or absent authorization yields `privacy_blocked`; model declarations cannot grant authorization. Full-screen use requires an explicit recorded reason in addition to those permissions. Rejected pixels are not persisted. Safe crops contain only the selected half-open image region, without scaling or coordinate inference.

Only explicit `image_rect` or full-image selection is supported; element-region requests are rejected by the parameter schema. Accessibility bounds, viewport rotation, window IDs, equal image/display dimensions, and an individual element's `password=False` do not establish screenshot pixel mapping or frame-wide sensitivity coverage. The driver never uses element bounds for cropping, masking, or geometric privacy decisions. Image-rectangle/full-image assertions need no pointer mapping, but both require an independent trusted current-frame privacy decision; a rectangle or one safe target cannot bypass absent whole-frame authorization.

One fresh `Device.take_screenshot(control=...)` call supplies the assertion and its step screenshot evidence. Any `Device.display_size(control=...)` query is serialized on the existing single owner worker; equal dimensions do not prove the same display. Public `Session.session_info().id` is process-local provenance only. Capture begins immediately before the screenshot call and finishes only after PNG validation; stale, negative, reversed, or overlong monotonic windows are rejected before provider work. There is no automatic recapture, cached frame, or request replay.

The host validates PNG size/IHDR/chunks and rejects `acTL`, `fcTL`, or `fdAT` as `frame_not_single` before provider work. It uses existing Pillow support for bounded lossless image-space crops, without claiming verified color-space/channel semantics. Structured exact-color claims yield `color_semantics_unverified`; capture-generation, same-display, or same-frame claims yield `display_identity_unverified`. Different image/default-display dimensions alone do not reject an ordinary image-space assertion.

Artifacts and `HostCaptureEnvelopeV1` are written only through the current Run's artifact store. Absolute, parent-traversing, symlink-escaping, or cross-Run references are rejected as `artifact_containment_violation`, never collapsed into `capture_failed`. Capture failures preserve only allowlisted SDK `backend_code`, `request_state`, public local `session_state`, and `stage`, retaining the distinction between `not_sent` and `response_unknown` without raw error text, paths, PNG bytes, prompts, or credentials. Explicit cancellation propagates without a business verdict or a second request; unknown in-flight outcomes remain observable.

Default-display physical dimensions come only from public `session.device.display_size(control=...) -> DisplaySize` on the owner thread. Successful width and height are actual integers in 1..2147483647; they define physical pointer coordinates in `0..width-1` and `0..height-1`. Context and each coordinate calculation consume current dimensions without caching or assuming an atomic screenshot/observation/action snapshot. The driver never substitutes hierarchy viewport, screenshot geometry, inferred insets, ADB, or private WebDriver state. An absent/incompatible API or failed query is an explicit non-success, not a fallback. Only internal point-based Strict/Replay consumes `reference_screen_size` for proportional scaling; online arguments cannot supply it.

`swipe` validates exactly one Models-owned mode. Untargeted direction preserves the existing 25%-to-75% display gesture. Explicit start/end executes physical coordinates, with internal Strict reference scaling only when supplied. Element mode resolves target/locator uniquely, reads `attributes=("bounds",)` through public inspection, and first computes a center-symmetric segment spanning the requested fraction of the element's first-to-last-interior-pixel axis; the effective omitted/null fraction is 1.0. The cross-axis point is its integer center, and direction determines endpoint order. Horizontal starts stay at least `inset = min(element_height // 2, element_width // 4)` inside the corresponding element edge: a rightward start is at least `x + inset`, and a leftward start is at most `x + element_width - 1 - inset`. Apply this start adjustment only when a positive directional span remains; do not collapse a narrow valid gesture. For a full-fraction rightward gesture, the endpoint is `min(display_width - 1, x + element_width)`, allowing the element's right boundary only when it is still a valid physical display pixel. Other endpoints and vertical gestures retain their fractional interior-pixel geometry. Bounds must be positive, fully within the current physical display, and provide at least two usable pixels along the gesture axis; integer rounding that collapses the original segment fails. Invalid, missing, ambiguous, off-screen, or degenerate bounds do not fall back to a display gesture. A successful calculation sends exactly one public `device.swipe_between` with the selected duration; it does not prove a slider value or replay the gesture automatically.

`press_key` preserves existing system Home and Back semantics. Case-insensitive `moveend`, `move_end`, and `end` map to KEYCODE_MOVE_END (123); `movehome` and `move_home` map to KEYCODE_MOVE_HOME (122). `Ctrl+End` maps to one public `Device.press_keycode(123, metastate=4096, control=...)` call using Android META_CTRL_ON (0x1000), not a sequence of unmodified events. Unsupported shortcut syntax is rejected without sending a partial key event. Key transport success does not prove application-specific cursor movement.

On first session-requiring operation, the driver lazily binds on its dedicated single-worker thread (`ThreadPoolExecutor(max_workers=1)`), allocates an ephemeral loopback TCP port (`127.0.0.1`), enters `Runtime.start_managed(...)`, and creates an Automation `Session` with `auto_launch=False`, `force_app_launch=False`, `no_reset=True`, `full_reset=False`, and `should_terminate_app=False`.

The private backend constructor accepts `uiautomator2_wait_for_idle_timeout_ms: int | None = None` under the exact built-in integer and Node/Appium-safe range contract owned by `AndroidHarnessSettings`. On owned Session creation, an explicit value is passed unchanged through the SDK public `create_session` keyword of the same name; None omits that keyword and selects no initial idle override. Zero is retained through an explicit non-None check. Ordinary FSQ and SDK defaults remain unchanged; the backend contains no benchmark, Clock, app-id, or task-specific idle selection.

A supplied borrowed Session cannot accept a new non-None initial idle override: construction rejects that combination as a configuration error before any SDK operation, rather than silently ignoring the value or mutating the borrowed Session. Borrowed Sessions with the default None retain their existing behavior.

The SDK owns conversion of the typed keyword to the new-session initial Setting. FSQ does not construct free-form capabilities/Settings payloads, access private SDK state, add a post-create Settings update/readback, or retry Session creation to apply the policy. A missing or incompatible SDK API remains an explicit failure under existing ownership and cleanup rules; there is no TypeError fallback or retry without the keyword.

This initial idle policy does not alter assertion semantic polling, per-inspection OperationControl budgets, capture or unavailable-session guards, error normalization, frozen results, reports, or terminal cleanup. An operation_timeout with response_unknown remains an operational non-success, not target_not_found or a successful assertion; ordinary operations never retry the business assertion or implicitly reconstruct its Session.

`close()` performs explicit terminal cleanup on that same owner thread. An active owned Session uses public `Session.quit()` followed by managed-scope completion. An uncertain or disposing owned Session uses public `Session.dispose(*, control: OperationControl | None = None) -> None`; if quit leaves the Session uncertain, the same close operation may explicitly dispose it. `SessionInfo.state == "disposed"` proves local terminal disposal and settlement of the owned managed service, not an Appium DELETE or confirmed remote Session close; `appium_session_id` remains historical evidence. A public disposal success supplies the managed-service settlement proof without accessing or separately releasing its usage token. Borrowed Sessions are not disposed by this driver.

When `Session.quit()` raises the SDK's `ResourceStateError` with code `session_quit_unknown` and leaves the owned Session uncertain or disposing, explicit `Session.dispose()` can settle that quit uncertainty within the same close flow or a later explicit continuation. Once public disposal succeeds with `SessionInfo.state == "disposed"`, all owned managed-scope obligations complete, and the owner-thread executor shuts down successfully, `close()` returns normally instead of rethrowing the settled quit error. The public disposal contract proves release of the local client and this instance's owned managed process group, streams, and locks; FSQ neither accesses private SDK ownership fields nor infers settlement merely from an absent process. A bounded, secret-safe diagnostic retains the quit error code and request state, `remote_quit_confirmed=false`, and the completed terminal-disposal fact. It is not a capability, replay step, device-restoration claim, or confirmed Appium DELETE.

The driver retains Session, Runtime, connection, managed-scope, and owner-thread resources needed to continue pending cleanup until their corresponding settlement succeeds. Public disposal preflight cancellation or timeout can leave the Session uncertain; disposal that has begun can remain disposing. Both retain ownership and permit a later explicit close to continue the same cleanup through public SDK APIs. Successfully completed stages are not repeated, and the worker is shut down only when pending cleanup no longer requires its owner thread. A successful close means every owned resource is settled; an unsuccessful close preserves pending ownership and reports failure rather than becoming an empty successful close.

Ordinary actions, observations, and context acquisition never dispose, reconnect, or create a new managed generation when a Session is non-active or owned cleanup is pending. They report the unavailable state without changing the SDK's quarantine or sending cleanup signals. Explicit close does not retry business operations, rebuild a Session, restore device state, kill the target app, or stop ADB. SDK terminal disposal is restricted to the exact owned managed connection; foreign or external ownership never grants cleanup authority. The driver consumes public lifecycle states, results, and errors only: it does not inspect private lease/process fields, infer ownership from a port or disk PID, or send process signals itself.

## Internal Structure

- Private `AppiumConnectAndroidDriver` backend implementation and Android capability declarations.
- `_visual_inspection.py`: private public-SDK visual provider adapter, same-frame evidence handoff, safe observation results, and driver integration; no host coordinate mapping.

## Python Architecture

- Architecture level: Level 2 Simple Package.
- Dependency direction: depends on Core Interfaces; never imports Harnesses or adapters.
- Rationale: one focused backend implementation is sufficient.

## Error Handling

Text entry returns normalized non-success results with safe diagnostics that distinguish an invalid input target, rejected or mismatched entry, and unavailable verification. Unavailable verification does not assert that the text was not entered. Input values, observed values, target parameter payloads containing input, and raw backend exception messages are not included in text-entry results or diagnostics; comparisons remain in memory. Runtime-secret resolution and execution evidence sensitivity remain owned by Core.

Input failure diagnostics preserve only safe SDK facts: allowlisted `code` as `backend_code`, enumerated `request_state`, bounded allowlisted `completed_steps`, an input-operation stage, and enumerated local `session_state` when publicly available. Literal and runtime-secret values, observed input text, raw SDK messages, request bodies, response fragments, and arbitrary cleanup text are excluded. Pre-inspection failure, write-response uncertainty, and post-verification unavailability remain distinct, and diagnostic collection does not issue device requests or mask cancellation or a primary failure. Local `closed`, `cleanup_pending`, and non-active Session states have distinguishable safe diagnostics; ordinary operations retain quarantine and do not dispose or reconnect. Runner primary action failures and secondary context/capture failures remain independently inspectable.

Primary action/session failures and secondary pending-cleanup failures remain independently inspectable through public exception or normalized runtime-result diagnostics. Pending cleanup failures are not reduced to warnings or hidden by a prior failed operation. The settled `session_quit_unknown` case defined above is diagnostic history, not a remaining cleanup failure; other errors are not swallowed merely because they share the `ResourceStateError` type. Session invalidity is not proof of disposal, and cancellation retains precedence without erasing pending-cleanup diagnostics. Failed disposal, scope completion, or executor shutdown does not clear the ownership needed for explicit continuation, permit implicit reconstruction, or report successful close.

## Verification Scope

Isolated device-free lifecycle verification consumes the real pinned SDK's public terminal-disposal contract and exercises pending ownership, explicit continuation, owned-resource settlement, failure propagation, and cancellation without mocking the lifecycle or usage authority under proof. It makes no device, application, or model calls and does not use or mutate shared SDK records, locks, frozen installations, or historical Run evidence.

Lifecycle verification distinguishes unconfirmed remote quit followed by fully settled disposal and normal idempotent close from disposal, managed-scope, or worker failure that still propagates and retains pending ownership. It proves that settled quit uncertainty remains observable without a false remote DELETE claim, including successful explicit continuation after an earlier failed disposal.

Device-free assertion verification uses the real SDK and Appium client with an isolated protocol peer to establish that unrequested assertion attributes are not fetched, requested predicates still govern consumer-visible results, and target ambiguity, unavailable values, cancellation, and response-unknown failures retain their existing semantics. It preserves SDK-internal reads required by a requested attribute, such as the `checkable` dependency of `checked`; it does not promise one HTTP request per attribute or a fixed device-side latency.

## Current Invariants

- Construction does not connect to a device.
- Compact UI snapshots preserve the documented normalized XML payload and safe fallback.
- Built-in Android context reports Session, current full physical display size from public `Device.display_size()`, backend (`appium_connect_agent`), and current-package metadata from public observations, without private probes. `TreeObservation.viewport` remains content observation metadata only. The optional `current_activity` field remains unavailable and triggers no separate foreground-activity request.
