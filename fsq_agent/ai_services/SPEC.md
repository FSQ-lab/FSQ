# Module: ai_services

## Purpose

Own FSQ visual assertion/inspection, completed-Case suggestion, and Quick Test intent analysis over neutral model calls. Services prepare inputs, supply private strict output schemas/parsers, and convert validated objects into FSQ results. They do not own supplier authentication, SDK objects, platform capture/coordinate conversion, installed-application discovery, persistence, platform actions, Case execution, candidate publication, or reports.

## Dependencies

- `models`: `AIAssertionRequest`, `AIAssertionResult`, and `ConfigurationError`.
- `config`: resolved `Settings` for service construction.
- `providers`: public configured-session factory and supplier metadata/lifecycle access.
- `agent_engine`: neutral text/image requests, generic output contracts/results, and safe model errors.
- Pydantic for private model-facing output schemas and strict business validation.
- Standard library file reading, MIME detection, JSON, timing, and immutable records.
- No dependencies on Core, Agent, adapters, execution, Application, or SDK packages. Core accepts an injected evaluator structurally and does not construct these services.

## Public Interface

- `AIAssertionEvaluator`: synchronous `evaluate(request: AIAssertionRequest, *, cancellation_check=None) -> AIAssertionResult` and `close()` operations, with an optional trusted cooperative cancellation collaborator for scoped tri-state visual evaluation across Android, iOS, macOS, Windows, and Web. The serializable request contains no live callbacks or SDK objects.
- `AIAssertionEvaluator.inspect(request: AIVisualInspectionRequest, *, cancellation_check=None) -> AIVisualInspectionResult` implements a separate observation-only protocol across all five platforms using the same configured model-session lifecycle and reasoning effort, without new constructor/factory/resolver parameters. A private implementation owns its strict summary/image-bounds schema. It validates authorized current-frame input, requested mode/region/candidate bounds and budget, performs at most one tool-free `Model.complete` request using `ImageContent` and a Pydantic output contract, and rejects invalid/refused/late output without repair/retries. Extract has no candidates; locate image bounds use full-image coordinates, never model-generated pointer coordinates. Public SDK adapter code constructs physical/logical pointer results only on platforms that support pointer mapping. Cancellation and primary/cleanup precedence are preserved; errors remain safe neutral engine failures, not assertion verdicts.
- `CaseSuggestionAnalyzer`: synchronous `analyze(*, parsed_case, execution_report) -> CaseSuggestionAnalysis` over completed execution facts.
- `CaseSuggestionAnalysis`: immutable summary, suggestion entries, and optional candidate Case YAML.
- `build_ai_assertion_evaluator(settings)` and `build_case_suggestion_analyzer(settings)`: create services from the selected supplier without inference.
- `check_case_suggestion_readiness(settings)`: safely constructs and closes a configured analyzer without inference or UI actions.
- Quick Test intent and target resolution: a synchronous public analyzer (`QuickTestIntentAnalyzer`) and configured factory (`build_quick_test_intent_analyzer`) interpret the current goal, selected platform, and host-supplied candidate inventory (for native platforms) or optional explicit starting URL (for Web) in a single tool-free `Model.complete` call into an immutable `QuickTestIntent` decision. The factory requires only the saved Provider and selected-platform inference policy, not a runnable application target or registered Workspace; it performs no inference during construction.
- For native platforms (`android`, `macos`, `windows`), `analyze` accepts a host-supplied bounded sequence of safe candidate summaries (`candidate_id`, `label`, `aliases`, platform identity) stripped of host-only fields such as `window_title_re` and `launch_args`. The model selects either one exact supplied `candidate_id`, or an explicit concrete local path/package written verbatim in the goal, or reports a structured non-executable outcome (`insufficient`, `missing_application`, `application_not_found`, `ambiguous_application`) with diagnostic fields (`target_name`, `candidate_ids`, `explanation`). When a goal requires starting from an entry application (for example, opening an app store or installer to install App X), the analyzer selects that entry application rather than claiming App X is missing or attempting installation.
- Security boundary: the analyzer rejects any invented `candidate_id` not present in the host-supplied inventory; an explicit native path/package is accepted only when it is a well-formed explicit reference from the goal; `launch_args` and `window_title_re` are never part of the model input or output contract. There is no verbatim substring `_grounded()` check on natural-language display names and no mutual-exclusion lock between explicit references and candidate selection beyond clean priority rules.
- For Web, an optional caller-supplied `--url` is validated by `validate_quick_test_web_url(url) -> str` as a single complete HTTP(S) URL before inference and locked unchanged as the starting `base_url`; the model evaluates actionability only. When no `--url` is supplied, the single tool-free model call either extracts `base_url` directly from the goal (completing `https://` for an explicit bare public domain such as `x.com` or `github.com/foo`, or `http://` for an explicit bare `localhost` / loopback address such as `localhost:3000` or `127.0.0.1:8080`, while never inventing a domain from memory or rewriting non-HTTP(S) schemes such as `javascript:`/`file://` into HTTP(S); host-validated by `validate_quick_test_web_url`) or classifies an address-free search/discovery objective (`reason="web_search"`, `base_url=None`, with a nonblank search subject). Malformed or unsupported extracted/supplied URLs fail with a safe address error rather than falling back to Web search.
- `validate_quick_test_web_url(url: str) -> str`: public deterministic, tool-free HTTP(S) URL validator shared by AI Services and Application. It validates one complete HTTP(S) URL (requiring `http` or `https` scheme, nonempty valid host including bracketed IPv6, valid port `1..65535` when present, no userinfo, whitespace, backslash, or control characters) and returns the validated URL unchanged, raising `ValueError` on invalid input. Natural-language prose boundary parsing is not performed in Python.

Service constructors accept a keyword-only `reasoning_effort: ReasoningEffort = "mid"` option while preserving existing assertion/suggestion constructor arguments. The factories pass the resolved selected-platform reasoning effort; direct callers that omit it remain supported. Each evaluation/analysis places that neutral value in its `ModelRequest`, without selecting a native enum or relying on SDK/server defaults.

The stable services, factories/readiness helper, and immutable service results are exported from `__init__.py`. Their callers are Application and entry/runtime composition; they are not supplier infrastructure exports. Service-specific output facts are local records; shared assertion request/result contracts remain in `models`.

## Model-Facing Output Contracts

Each service supplies an `OutputContract` built from its private Pydantic output model's JSON Schema and parser. Root schemas are objects, every declared field is required, and nullable fields are present with `null` when absent. Root objects and nested output records forbid additional properties. Field validation is strict: booleans and text are not obtained through coercion. The parser validates the whole JSON document, allowing ordinary JSON whitespace but not Markdown fences, surrounding prose, extracted substrings, non-finite numeric extensions, or non-object roots. Services consume only the expected typed `parsed_output`; a missing or wrong parsed object is `invalid_output`, not permission to parse result text again.

- Visual assertion model output across Android, iOS, macOS, Windows, and Web uniformly contains only `outcome=passed|failed|inconclusive`, nonblank `explanation`, and required nullable finite `confidence` in `0..1`; legacy two-state boolean model output schemas are retired. `inconclusive` is a valid uncertain model observation, never a false boolean verdict. Host-owned reason, conflict, identity, usage, timing, capture, and authorization facts are not model-supplied output fields. Strict whole-document parsing rejects prose, fences, non-finite numbers, unknown fields, and missing nullable fields without repair or fallback parsing.
- Case suggestion output contains only `summary`, `suggestions`, and `candidate_case_yaml`. `summary` is a nonblank string normalized by stripping surrounding whitespace. `suggestions` is a possibly empty array of objects containing only required nonblank string `kind` and `message` fields, also stripped of surrounding whitespace; kinds are not a closed enum. `candidate_case_yaml` is null or a nonblank string normalized by stripping surrounding whitespace, without another YAML formatter. Conversion returns the frozen `CaseSuggestionAnalysis` and immutable suggestion entries. A candidate string is not proof of valid FSQ YAML or successful execution; Application and Case DSL own validation and publication.
- Quick Test output distinguishes a sufficient test intent from non-executable outcomes (`insufficient`, `missing_application`, `application_not_found`, `ambiguous_application`) and supplies structured target resolution (`candidate_id`, `explicit_reference`, `base_url`, `target_name`, `candidate_ids`, `explanation`). It does not invent actions, expectations, or an application absent from the current goal. A short but actionable goal is not rejected for length; naming only an application or topic is not sufficient to invent a smoke test.
  A clearly scoped request to view, inspect, browse, or explore the identified application is actionable intent even without a rigid QA assertion: its checkable outcome is delivery of truthful observations from that authorized flow. For native platforms, the model selects an exact `candidate_id` from the host-supplied inventory or an explicit concrete path/package from the goal, distinguishing the entry application (such as an app store or installer) when the goal begins there without performing implicit installation. For Web without a caller-supplied `--url`, the model either extracts a concrete starting `base_url` or classifies a clear address-free search/discovery objective (`reason="web_search"`, `base_url=None`) without inventing a website domain from memory. Model output never supplies `launch_args` or `window_title_re`, and never establishes installation, readiness, or test success.
  For iOS, the analyzer accepts only the exact `candidate_id` of a supplied candidate or a legal bundle ID or Simulator `.app` reference quoted verbatim from the goal. Candidate metadata is untrusted data, not prompt instructions. Guessed, transformed, or absent-from-goal explicit references are rejected; Environments validates the concrete target and selected device. Configured `xcode_org_id`, `xcode_signing_id`, and `updated_wda_bundle_id` are not model input or output fields, and model-generated values never bind execution settings.

## Internal Structure

- `__init__.py`: public service, factory, result, and readiness exports.
- `_factory.py`: configured service construction and safe suggestion readiness.
- `_ai_assertion.py`: private assertion output model/schema/parser, screenshot/text input preparation, prompting, timing, and parsed-verdict result construction.
- `_visual_inspection.py`: private strict observation output/schema/parser and neutral model-request/evaluation implementation; no SDK import or coordinate mapping.
- `_case_suggestion.py`: private suggestion output models/schema/parser, read-only completed-Case prompting, and immutable service result conversion.
- `_quick_test.py`: private single-call Quick Test decision output schema, prompt builder, inventory-membership validation, and the exported `QuickTestIntentAnalyzer` and immutable `QuickTestIntent`; `_factory.py` exports `build_quick_test_intent_analyzer`.
- `_web_addresses.py`: private implementation of the exported `validate_quick_test_web_url` deterministic HTTP(S) URL validator shared by AI Services and Application.

## Python Architecture

- Architecture level: Level 2 Simple Package.
- Public API: stable services, their factories/readiness, and service-specific result.
- Internal modules: `_*.py` files are private.
- Domain boundaries: FSQ assertion, suggestion, and Quick Test intent policy only; model invocation delegates downward.
- Boundary models: private Pydantic model-facing outputs, shared FSQ assertion models, immutable service results, and neutral engine request/results. Private output models remain in their owning service modules and are not exported or placed in a shared business-schema catalog.
- Dependency direction: business callers consume services; services consume public providers/engine APIs; neither providers nor engine depends back on services.
- Rationale: focused inference services share configured model access without another service registry or persistence layer.

## Error Handling

Visual assertion failures across all five platforms map to `outcome="inconclusive"` (`status="inconclusive"`, `passed=False`) with an allowlisted reason: unavailable configuration, authentication, rate limiting, refusal, provider timeout, unknown in-flight completion, invalid output, and input/capture/privacy/budget failures never become assertion failure. Safe neutral engine category/reason metadata is retained without copying raw response, exception, parser, credential, or SDK content.

Case suggestions propagate neutral generation/validation failures instead of converting malformed model output into a configuration error or a successful empty analysis. Application retains `case.suggestion_failed`, completed Run/report truth, and candidate publication authority without expanded HTTP/CLI result fields. The neutral cause remains in the service/error chain.

Quick Test propagates neutral inference/output failures separately from valid non-executable intent outcomes (`insufficient`, `missing_application`, `application_not_found`, `ambiguous_application`). Application owns the public error category, cache-refresh retry policy, and termination policy. Analysis cannot ask a follow-up question, repair rejected output with another inference, change Provider settings, inspect the host, or launch an application. It receives only the current goal, selected platform, optional explicit Web URL, and host-supplied bounded candidate summaries (stripped of host-only `window_title_re` and `launch_args`), never previous goals or workspace secrets.

Scoped resources close on every path. Cleanup does not mask a primary failure or cancellation, including a failure already represented as an inconclusive/error result; cleanup-only failures remain independently visible. Explicit cancellation and interruption propagate rather than becoming business verdicts. There is no semantic retry, provider fallback, JSON repair, or detached inference accepted as a late verdict.

## Current Invariants

- Each evaluation/analysis makes at most one tool-free `Model.complete` request with a caller-owned output contract through the configured provider session, with no semantic retry, JSON repair, free-text fallback, Runner, action tool, handoff, or implicit Provider configuration change. Input, privacy, and deterministic gates may reject before any inference.
- Visual assertions and Case suggestions use the same resolved platform reasoning-effort policy as the Coding Agent business phases. Services retain their construction-time effort value, do not refresh it mid-task, and do not add automatic effort tuning, a native mapping, or a retry loop. Explicit low connection testing remains owned by Providers and does not alter service policy.
- Assertions use the selected provider/model without a separate override. All five platforms require a current, validated, Run-contained capture and trusted authorization; they never fall back to text-only evaluation or historical image/digest reuse.
- Visual evaluation across all five platforms checks declared surface/region, upload/privacy policy, encoded/decoded image budgets, PNG single-frame validity, monotonic freshness, and capture identity before external processing. Defaults and hard bounds are Models-owned. At most one active evaluation is permitted per evaluator; exceeding concurrency or input bounds is `budget_exceeded`. A provider timeout is inconclusive; cancellation remains cancellation, and a response observed after the deadline is discarded without retry.
- Deterministic adjudication compares only host-produced same-target exact property/value facts against structured expectations where supplied; unknown, not-applicable, clipped, stale, or unrelated facts are not counterevidence. Contradictory deterministic evidence forces `failed` and marks `deterministic_conflict`, even for model passed. A valid model failed remains failed when deterministic facts support the expectation, but the conflict is exposed. Exact accessible semantics are not delegated to visual approximation, and no free-text keyword matcher claims semantic equivalence.
- Visual assertion model instructions isolate the assertion from untrusted screenshot/context data, prohibit following embedded instructions or proposing tools/actions, and require an inconclusive response when visual evidence or instruction/data separation is uncertain. Only schema-valid evidence-based verdict fields are accepted; a model's own assertion of safety is not external-processing authorization. Controlled adversarial-image verification does not establish a general proof of model prompt-injection immunity.
- Assertion results retain safe explanation/confidence, measured latency/usage, provider identity, capture/region provenance, and references. Approved detailed prompt/output evidence remains Run-local and redacted; operational logs, exceptions, and model-facing tool summaries do not copy credentials, PNG bytes, unrestricted prompt text, or hidden reasoning.
- Suggestion analysis consumes parsed source Case data and bounded completed execution facts. Its prompt prohibits changing completed status/facts or initiating another run; the service cannot invoke UI actions. A missing nullable field is invalid, not an implicit absent candidate. Application owns candidate validation, source preservation, persistence, and publication rules.
- Public evaluation and analysis remain synchronous. Provider adaptation bridges asynchronous invocation with fresh loop-scoped resources and closes on every path. Service reuse does not reuse a closed async client.
- Readiness sends no inference, constructs no harness, and exposes safe verdict/message/action only.

- Quick Test `analyze` makes at most one tool-free `Model.complete` request per call. Application alone owns any permitted cache-miss refresh and second decision, including for iOS Simulator; there is no second decision for a physical iOS device.

## Verification Scope

Verify strict whole-document validation and required nullable fields through the engine conversion/parser boundary, three-way assertion outcomes with safe category/reason metadata, evidence/timing/usage preservation, suggestion immutability and candidate normalization, and scoped cleanup with primary-error/cancellation precedence. Neutral model-session doubles honor output contracts and return parsed values; they do not depend on production text fallbacks. Actual private service schemas participate in both pinned-client controlled-transport checks. Application integration verifies no candidate publication after invalid analysis and preservation of completed Run/report facts. Factories/readiness and caller imports use this public package without inference, extra actions, or Core/provider dependency cycles.

Quick Test verification distinguishes short sufficient goals, missing/unfound/ambiguous applications, entry-application selection (such as store/installer flows), host-inventory `candidate_id` selection, rejection of invented `candidate_id` values, explicit native path/package references, Web explicit `--url` locking, model-extracted `base_url` validation, address-free Web search classification, malformed/refused/timed-out output, and safe resource cleanup. The actual intent schema participates in the same configured-Provider and controlled-transport contracts without live credentials or UI actions.

Web URL validation verification covers valid HTTP(S) URLs (including ports, paths, queries, fragments, percent escapes, and bracketed IPv6) and rejection of blank, non-HTTP(S) schemes, missing host, userinfo, whitespace, backslashes, control characters, and invalid ports. Application-through-shared-Execution tests assert that the validated starting URL reaches frozen `harness.web.base_url` unchanged.

Web search verification distinguishes a clear discovery goal from a bare topic or an unspecified website test. Classification is not proof that a search occurred or that an answer is correct; actual browser activity and final evidence requirements belong to execution and goal verification.

Effort verification covers configured non-default propagation from each factory into the service's neutral request, compatible direct construction with the mid fallback, invalid-value engine failure without inference, and no-inference readiness. Native serialization is verified through the pinned-client transport checks; output parsing, one-logical-request behavior, and cleanup remain independent of effort.
