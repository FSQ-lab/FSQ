# FSQ v0.3.9

`fsq-agent` 0.3.9 pins the public `appium-connect-agent==0.1.4` and `lxml==6.1.0`. Upgrade with `python -m pip install --upgrade fsq-agent==0.3.9`. Existing workspace configuration does not need migration for these changes.

- **Visual tools:** Android, iOS, and macOS use SDK-backed capture for AI inspection and assertion. A host may opt eligible tools into a Run via `visual_ai_eligible`, but each captured frame still requires independent authorization and a non-sensitive classification. Mac2 localization requires SDK-supported display mapping. Use `sample_color` for deterministic local RGB; it does not upload an image.
- **Finder:** Search suggestions are clicked only after target identity and the actual pointer hit are verified. Unknown mutation results are not replayed.
- **Pages and other eligible macOS targets:** Path-based activation can reuse a healthy Finder anchor for the same verified installation. Rejected native snapshots report attributable permission-modal or foreground mismatch conditions without substituting Finder evidence or interacting with a system permission dialog.

## Verification scope

Development-candidate checks confirmed visual request eligibility and zero upload under frame refusal, Finder search suggestion dispatch, and all 13 Pages C-modal acceptance checks, including the rejected snapshot diagnostic. A separate 10-task MacArena strict-upstream regression on FSQ candidate `52f01aa909fb` with the development SDK 0.1.3 wheel recorded 2 passes, 7 unsatisfied goals, and 1 oracle script error. This is not a score for the published FSQ 0.3.9 / SDK 0.1.4 pair.
