# Module: drivers.macos

## Purpose

Implement macOS desktop automation through the `appium-connect-agent` public Python library (`appium_connect_agent` backend), including lazy thread-affine managed loopback Appium server and Mac2 `Session` lifecycle, explicit application lifecycle, desktop actions, compact semantic observations, assertions, and safe failure normalization.

## Dependencies

- `core.interfaces.MacOSDriverInterface`, `capabilities`, and macOS parameter/result models.
- Optional `appium-connect-agent` (`appium_connect_agent.contracts`, `appium_connect_agent.runtime`, `appium_connect_agent.automation`), imported lazily at runtime without direct `Appium-Python-Client`, `selenium`, or private WebDriver access.

## Public Interface

Instances satisfy `MacOSDriverInterface`; the concrete backend class is private outside Drivers and composition.

`ui_snapshot` returns bounded compact evidence from `Session.observe_tree()` in direct mode and the driver's private native AX collector in blacklist fallback mode. The direct path retains the primary-window fallback for `observation_too_large` and adaptive depth and sibling compaction. There is no device-clock probe or element-query mode.

`take_screenshot`/`takeScreenshot` captures a current Mac2 PNG frame through `MacOSTakeScreenshotParams`, returning raw PNG bytes for Harness persistence (`ArtifactStore` screenshot artifact plus `byte_length`) or a normalized `observation_error` envelope with allowlisted capture diagnostics on failure. In Finder-anchored native AX mode on `darwin` (when `/usr/sbin/screencapture` is available on standard `PATH` and no explicit sub-second caller test timeout override is supplied), if `Session.device.take_screenshot` times out or raises a transient backend error, `_screenshot_impl` falls back to a bounded silent `/usr/sbin/screencapture -x -t png` capture so post-step evidence collection does not fail or quarantine a live desktop session.

`inspect_element` (`inspectElement`) inspects one uniquely resolved element via `Element.inspect` (or the live native AX element adapter in Finder-anchored mode) for a non-empty subset of the 14 Mac2 attributes (`id`, `text`, `type`, `label`, `title`, `value`, `placeholder_value`, `element_type`, `enabled`, `focused`, `selected`, `hittable`, `displayed`, `bounds`), returning unclipped strings, explicit observation states, and integer `{x, y, width, height}` bounds. Whenever `text` or `value` is requested, the driver inspects `type` first and withholds `text`/`value` (`state="unavailable"`, `reason="protected_text"`) without querying them if `type` is `SecureTextField` / `XCUIElementTypeSecureTextField` or unknown; glyph-only mask strings are likewise marked unavailable.

`inspect_with_ai` uses the shared SDK-backed delegate for extract and locate on the owner worker. Locate requires SDK-validated single-main-display mapping; unsupported mapping returns `pointer_mapping_unavailable`. Both AI visual tools consume just their authorized SDK frame, without native screenshot fallback. `sample_color` delegates to SDK `Device.sample_color` on the owner worker with no provider call. `assert_with_ai` remains inconclusive before capture for exact color or display identity.

`assert_with_ai` (`assertWithAI`) evaluates scoped image-space or reasoned full-screen visual assertions through the shared tri-state (`passed | failed | inconclusive`) contract, sharing one privacy-approved single-frame PNG with step evidence and adjudicating structured same-target Mac2 deterministic facts from `inspect_element` so contradictory facts force `failed` (`deterministic_conflict=True`).

`assert_not_visible` (`assertNotVisible`) polls `Element.inspect(attributes=("displayed",))` on semantic or element-locator targets (rejecting coordinate-only points), passing on `displayed=False` or definitive `target_not_found`, reporting ambiguity when multiple matches persist, failing with `assertion_error` if still visible at timeout, and never treating `response_unknown` or inactive sessions as absence.

`assert_state` (`assert`) requires a non-empty element locator on `params.element` and performs branch-minimal inspection: text assertions take precedence (checking `type` first before reading `value` or `text` so `SecureTextField` fails safely without plaintext reads; `attribute="auto"` selects the first available value in `value`, `label`, `title`, `text`); state-only assertions request only explicitly supplied booleans in canonical order `("enabled", "focused", "selected", "hittable", "displayed")` with strict boolean equality; locator-only existence assertions request only `("enabled",)` to prove unique resolution.

`scroll_on` (`scrollOn`) uniquely resolves a semantic/locator target's live `bounds` center (without falling back to coordinates on miss or ambiguity) or consumes an explicit coordinate-only `point`. It dispatches through `Session.device.scroll_at` in direct mode and `NativeMacOSDesktop.scroll_at` for native targets; the latter accepts integer-valued Quartz deltas without sign inversion.

`press_key` (`pressKey`) normalizes whitespace, hyphens, and underscores in named key tokens before `MACOS_KEY_NAMES` lookup, mapping standard desktop/browser aliases (`ArrowUp`/`ArrowDown`/`ArrowLeft`/`ArrowRight`, `UpArrow`/`DownArrow`/`LeftArrow`/`RightArrow`, `Up`/`Down`/`Left`/`Right`, `Enter`/`Return`/`NumpadEnter`/`KpEnter`, `Backspace`/`Bksp`/`Delete`, `Del`/`ForwardDelete`, `Space`/`Spacebar`, `PageUp`/`PgUp`, `PageDown`/`PgDn`, `CapsLock`, `Ins`/`Insert`/`Help`, `Clear`, `Esc`/`Escape`, `Tab`, `Home`, `End`, `F1`–`F19`, and `XCUIKeyboardKey*` constants) to Mac2 `XCUIKeyboardKey*` identifiers while rejecting unsupported multi-character key names with `ConfigurationError`.

Native-target `press_key` uses the SDK's physical key subset (ASCII letters/digits and SDK-supported named navigation and function keys) and event-local Command, Shift, Option, and Control modifiers. An unsupported native key or modifier is a configuration error, not a locator error. Literal Unicode or punctuation entry uses `type_text`. Native drag duration defaults to 250 ms and is bounded to the SDK's 50–5000 ms interval.

## Internal Structure

- Private `AppiumConnectMacOSDriver`, bounded tree/candidate helpers (`_elements.py`), native AX helpers (`_native_fallback.py`), and macOS capability declarations. Visual inspection uses `drivers/_visual_inspection.py`.

## Python Architecture

- Architecture level: Level 2 Simple Package.
- Dependency direction: depends on Core Interfaces; never imports Harnesses or adapters.
- Rationale: one focused backend implementation is sufficient.

## Element Resolution

- All structured selectors constrain the same element. Direct mode uses WDA selectors; fallback uses XPath 1.0 and native AX node matching, with exact original AX role matching. Finder-anchored locators, including absence assertions, are evaluated only within the application, window (or bounded application-child fallback), and active-menu projection defined below; pruned branches do not participate. Unsupported selectors and incomplete observations of the requested projection cannot prove uniqueness or absence.
- Literal values are safely encoded for XPath and `-ios predicate string` query syntax, including apostrophes, quotes, and backslashes. Backend-owned selector syntax is not assembled by interpolating unescaped user text.
- Element-targeted actions, observations, and assertions require a unique live match. Multiple distinct matching elements produce a `target_resolution_error` (`resolution_reason="ambiguous"`) with bounded candidate summaries, not a first-match action. Candidate descriptions include available type, text, state, geometry, and complete usable locator signals; uncertain uniqueness never permits an action.
- For transient Finder search suggestions, route by actual logical target, never WDA anchor identity. Before the first mutation, prove a unique enabled menu item in the current search field/menu/window ancestry, real foreground Finder PID and bundle, supported single-main-display coordinates, and matching system-wide and Finder-app AX hits attributable to that same item. Role, title and geometry must agree. Final validation follows session/liveness work within the operation deadline. Failed proof dispatches zero mutations; successful proof dispatches one SDK `Device.click_at`. No WDA element, coordinate or keyboard fallback, and no replay after `response_unknown`. Ordinary Finder controls and Finder-anchored iWork are unaffected by this route.
- Direct pointer dispatch uses WDA Element and Device operations. Native AX mode or a logical target distinct from the WDA host routes all business input through public SDK `NativeMacOSDesktop`, with no WDA input fallback. Semantic pointer targets are resolved in a fresh foreground AX tree and checked by live system hit, target PID, and AX identity or descendant relationship; same-process menus and popovers remain eligible. Explicit coordinates require a live hit owned by the target PID and never substitute for failed semantic resolution. The SDK callback repeatedly verifies the original PID, bundle and pinned installation; unverified or foreign hits and foreground fail closed. Wheel deltas retain the tool's Quartz convention (positive up/left).
- Display-clipped labels and values are never advertised as complete exact-match locators. Complete locator values remain separate from bounded display previews; values exceeding response limits are explicitly marked unavailable rather than silently shortened or converted to broad prefix matches. Returned locator candidates are revalidated against live state before actions and do not promise cross-session stability.
- Targeted text entry retains displayed/editable preflight, text-independent identity binding, focus verification in native mode, and value readback for readable controls. Direct sessions use Appium element/device keyboard methods. Native input without a locator types into current focus without clicking unless coordinates were explicitly supplied. Untargeted `clear=true` fails before input. Uncertain delivery is not replayed. Secure entry does not read or compare plaintext. Input dispatch without readback does not verify UI effect; readable value confirmation does not verify document commit or persistence.

## Structured Observation

- Compact tree output preserves interactive element identity and useful state when present in the source. Display text remains bounded, with explicit clipping metadata; default-state omission is documented. Requested depth limits identify truncated children instead of implying a complete subtree. Parsing and scanning enforce resource bounds and reject DTD/entity declarations.
- Snapshot diagnostics distinguish backend source facts and compact-tree coverage without embedding unrestricted raw source. A screenshot and a tree are separate observations and are not described as an atomic capture. A compact tree is observation context rather than proof that an omitted control is absent.
- Native AX snapshots must be attributable to the actual logical target. Empty or unavailable target AX evidence or unverified foreground produces a safe observation error, not the Finder WDA host tree.
- For a rejected native AX snapshot, read-only diagnostics distinguish an attributable visible system permission modal (`observation_error`, `backend_code="permission_modal"`) from a verified foreground bundle mismatch without such a modal (`observation_error`, `backend_code="foreground_mismatch"`, with safe logical and actual bundle IDs). Modal diagnosis does not require the system dialog process to own the foreground. Unknown foreground or unavailable evidence alone does not establish either diagnosis. Diagnostic rejection supplies no tree, does not interact with system UI, and does not replace or invalidate a healthy anchored session.

## Error Handling

Existing normalized action/result and failure-category envelopes remain intact. Selector/argument validation errors map to `configuration_error` (`resolution_reason="invalid_locator"`); definitive `target_not_found` and `target_ambiguous` on an active session map to `target_resolution_error`; non-definitive `TargetError` (including `request_state="response_unknown"`), `CommandError`, `OperationTimeoutError`, unavailable/quarantined sessions, and unsatisfied text-entry postconditions map to `action_error` (or `observation_error` for observations) with allowlisted `_safe_diagnostics` (`backend_code`, `request_state`, 32-hex `operation_id`, allowlisted `completed_steps`, `session_state`, and `stage`). Literal inputs, secrets, observed input text, and raw backend exception text are excluded from diagnostics.

## Verification Scope

- Offline verification covers literal escaping, conjunctive matching, ambiguity without side effects, safe error classification, text-entry value verification and fallback, and display-preview versus exact-locator separation.
- Snapshot verification compares sanitized source and compact output for interactive nodes, duplicate labels, offscreen nodes, missing state, depth clipping, and malformed source. Real-browser success is not inferred from offline tests or screenshots alone.

## Current Invariants

- Construction and registry discovery do not import `appium_connect_agent`, start Appium, or launch an application.
- All `Runtime` and `Session` operations execute on one driver-owned single-worker thread to satisfy `appium-connect-agent` owner-thread affinity, propagating cooperative cross-thread cancellation via `OperationControl` on a 25ms poll loop.
- The driver defaults to direct bundle-bound WDA and standard `macos: keys`. `native_ax_fallback_bundles=None` uses `XCTEST_QUIESCENCE_BLACKLIST_BUNDLES`: `com.apple.iWork.Keynote`, `com.apple.iWork.Pages`, `com.apple.iWork.Numbers`, `org.libreoffice.script`. An explicit sequence replaces that set; an empty sequence disables fallback.
- Finder anchoring requires an eligible bundle, Darwin, owned resources, `skip_app_kill`, trusted AX, and no startup arguments. Explicit `.app` paths are validated and resolved to `CFBundleIdentifier`; a conflicting supplied bundle ID fails. A healthy anchor is reused for the same verified installation with `new_session=false`; eligible path-based creation also uses a Finder anchor. A path must select that installation rather than another copy with the same bundle ID. `cleanup_pending` blocks ordinary reuse; explicit replacement must settle prior owned resources.
- Native activation verifies a stable real foreground PID and bundle within a bounded deadline, distinguishing unobservable foreground, a target not in foreground, and an attributable system permission modal. Unknown foreground never implies Finder. System permission dialogs are not accepted or dismissed automatically.
- Foreground failures direct callers to reactivate the explicit logical bundle with `new_session=false`, not rediscover it with `auto`; explicit `auto` remains available for intentional foreground discovery.
- Private `_native_fallback.py` owns AX diagnostics, observation, focus validation and hit testing; the SDK owns native event posting. Native AX reads role and subrole before requesting `AXValue`; secure fields and unknown types cause zero `AXValue` IPC calls. Borrowed sessions and argument-bearing direct sessions do not enable Finder anchoring.
- Native AX tree capture reads application identity, then `AXWindows` and the top-level `AXMenuBarItem` entries under `AXMenuBar`; it falls back to bounded application `AXChildren` only when there are no windows. Only selected or expanded menu bar items contribute their open menu and its immediate entries; unopened menus and nested submenus are not traversed. Each visited AX reference gets its own messaging timeout, capped by the remaining capture budget; attribute IPC is budget-checked and node attributes precede child traversal. A communication failure, invalid reference, or disabled AX API stops reads on that node and marks coverage incomplete without discarding healthy siblings; unsupported and missing attributes do not stop the node.
- Native AX capture queries `AXSubrole` only for `AXTextField`, `AXTextArea` and `AXStaticText`, and never reads `AXValue` when their subrole read fails with `kAXErrorFailure` (`-25200`). For optional single-value metadata, `-25200` makes that attribute unknown without making the topology incomplete; a selector that depends on the unknown attribute must not use it to prove uniqueness or absence. For `AXRole`, `AXWindows`, `AXMenuBar` and `AXChildren`, `-25200` makes the requested projection incomplete. Communication failure, invalid reference, disabled AX API, and depth, node or time truncation continue to make the projection incomplete.
- Bounded native AX projection includes open Finder search suggestion menus rooted in the application or search-field subtree, including intermediate native roles. It preserves role, ancestry and bounds; incomplete coverage cannot prove uniqueness or absence.
- When a Finder-anchored capture has unavailable optional metadata, XPath resolution only proceeds for basic tag paths with optional positive integer positions whose tags do not depend on failed reads. Other XPath expressions are inconclusive under partial metadata; XPath 1.0 remains available when no optional metadata read failed.
- Owned sessions retain the 900-second command-idle default and `skip_app_kill=True` default. An explicit `.app` path must select that installation rather than substituting another app with the same bundle id. An explicit `skip_app_kill=False` remains effective for the logical target, not merely the Finder anchor.
- Context obtains optional logical main-display dimensions from public SDK `macos_main_display_bounds` on Darwin; unavailable geometry stays unknown. Context does not query an accessibility tree. Explicit SDK operations preserve allowlisted timeout and request-state provenance; evidence-only errors do not replace a failed action's diagnosis. Closing an explicit session remains eligible in pending or uncertain state and settles resources on their owner worker.
- `Session` creation is explicit through `launch_app`. Before reusing an owned session after at least 45 seconds of inactivity—or when an owned session enters `"uncertain"` state after `operation_timeout` (tracked across `_run_tool`, `screenshot`, and `inspect_with_ai`)—the driver probes `Session.ensure_alive` on the owner thread; if `ensure_alive` fails during an idle liveness probe or cannot restore an active owned session after `operation_timeout`, and `skip_app_kill` is `True` with a known target identity, the driver cleanly disposes and replaces the stale owned `Session` and refreshes `_last_operation_finished_at` without killing desktop apps. If clean teardown of the stale owned resources succeeds during `skip_app_kill=True` recovery (`_session is None` and no uncleaned runtime scope remains) but replacement `_create_session` transiently fails, the driver records `_recoverable_session_loss = True` with `_cleanup_pending = False` so subsequent actions or `launch_app(new_session=False)` can retry clean session creation instead of permanently deadlocking in `cleanup_pending`; `_cleanup_pending = True` remains strictly enforced when teardown itself fails, when `skip_app_kill` is `False`, or when unrecovered `"uncertain"` sessions stem from non-timeout causes or ambiguous creation (`session_create_unknown`). Borrowed sessions and unrecoverable non-active sessions fail with `session_unavailable` without implicit teardown. `close()` settles `session_quit_unknown` cleanly when subsequent `Session.dispose()`, managed scope exit, and worker shutdown all succeed, retains the exact worker executor and primary quit error (`BaseExceptionGroup`) if worker shutdown fails so a retry can complete terminal disposal, and preserves `_terminal_disposal_diagnostic` across idempotent post-settlement `close()` calls.
