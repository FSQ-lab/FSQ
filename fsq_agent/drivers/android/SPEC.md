# Module: drivers.android

## Purpose

Implement Android automation through the `appium-connect-agent` `Runtime` and `Automation` public contracts (`appium_connect_agent` backend), including lazy thread-affine managed Appium server and Automation session lifecycle, declared actions, screenshot and compact `<hierarchy>` XML UI observation, device context, and backend failure normalization.

## Dependencies

- `core.interfaces.AndroidDriverInterface`, `capabilities`, and Android parameter/result models.
- Optional `appium-connect-agent` (`appium_connect_agent.contracts`, `appium_connect_agent.runtime`, `appium_connect_agent.automation`), imported lazily at runtime without private WebDriver access.

## Public Interface

Instances satisfy `AndroidDriverInterface`; the concrete backend class is private outside Drivers and composition.

`input_text` retains the existing target-or-locator parameter contract and replacement semantics. It establishes that the resolved target is an editable text control before clicking, clearing, or writing. Target existence, clickability, focusability, or focus alone is not sufficient; keyboard containers and other non-editable targets are rejected without text-entry side effects.

Successful text entry requires a bounded read-only postcondition check of the original target after replacement. Before any click or write, an observed nonempty raw resource-id is bound through public `Session.element("id", ...)` and checked for unique resolution and matching original type, package, id, and bounds. Standard fully qualified `package:id/name` values use exact native id matching without enabling raw-id Settings changes; nonstandard observed ids use the SDK's public `raw_id=True` guard to prevent autocomplete from changing their meaning. Post-write inspection re-resolves through that bound identity instead of the original mutable text or positional locator, preserves type/package/id, and permits bounds movement only for this proven identity. Original compound locator constraints govern initial target selection; binding never selects an arbitrary duplicate-id target. When no raw id is available, only an already demonstrably unique, text-independent locator with unchanged identity and bounds can establish the postcondition; an ambiguous or mutable-text/class-only target without a provable binding fails closed. The observed value must equal the requested string, including empty strings and Unicode. A non-throwing backend call is not acceptance, and no implicit write retry, alternative target, or focus-only keyboard fallback is permitted.

`input_text` pre-entry inspection requests `("type", "id", "package", "enabled", "displayed", "password", "text", "bounds")` to establish editability, visibility, readability, and target identity. Post-entry verification requests only `("type", "id", "package", "enabled", "password", "text", "bounds")`; it does not request the unused `displayed` attribute. Stable-id binding checks only the identity attributes necessary to prove it is the original pre-entry target, before mutation. Enabled-state, unmasked-readability, and exact-text postconditions are required independently of the chosen binding.

`assert_state` (`assert`) requests only the attributes required by its active assertion branch, without changing its public parameters, text-predicate precedence, target-uniqueness checks, or result semantics:

- The text-assertion branch requests only `("text",)`, including when an element also supplies state predicates; the existing text branch retains precedence and the driver does not add state assertions that branch does not evaluate.
- A state-only assertion requests exactly the explicitly supplied boolean state fields, including expected `False`, once each in canonical order `("enabled", "checked", "selected", "clickable", "focused")`. Unasserted fields are not requested.
- A locator-only existence assertion requests only `("enabled",)` as the single observation needed to use the SDK's non-empty inspection contract. Its success requires unique target resolution, not an enabled value of `True`; this does not turn existence into an enabled-state or visibility assertion.
- `assert_visible` and `assert_not_visible` request only `("displayed",)` and retain their existing visibility, absence, and ambiguity semantics.

The reduced `assert_state` inspection retains `OperationControl(timeout_seconds=10.0)` and the existing semantic-wait and cancellation behavior. Its existing target-not-found semantic polling is preserved; operation timeouts and response-unknown failures remain operational non-successes, without business retry, implicit reconnection, or timeout expansion. Visibility assertions retain their existing polling policies. Attribute selection does not change initial idle policy, SDK-internal attribute dependencies, evidence capture, reports, or cleanup.

Locators use only the supported SDK `Session.element` strategies `id`, `accessibility id`, and `xpath`. A single resource-id or accessibility-id retains its existing native strategy; compound string locator fields retain conjunctive XPath semantics. Expected boolean states are assertion predicates, not locator predicates. The driver neither emits unsupported `-android uiautomator` or `class name` strategies nor drops compound constraints to choose a faster but different target.

`ui_snapshot` (`uiTree`) consumes public `Session.observe_tree()` `TreeObservation` and deterministically synthesizes compact Android `<hierarchy>` XML in `{"xml": ..., "coverage": ..., "compaction": ...}`. It preserves `resource-id`, `content-desc`, `text`, `class`, `package`, `bounds`, `window-id`, and non-default boolean states (`enabled="false"`, `displayed="false"`, `focused="true"`, `checked="true"`, `selected="true"`), folds meaningless layout-only wrapper nodes, clips `text` and `content-desc` to the first 50 characters, and falls back safely to complete unfolded `TreeObservation` XML serialization on unexpected compaction errors without accessing any private `_driver` handle.

`inspect_element` (`inspectElement`) is a driver-owned observation-kind capability using public `Element.inspect` for one uniquely resolved target and only the explicitly selected safe attributes. It preserves full `text` and `desc`, without the compact snapshot's 50-character clipping, and returns each requested attribute's explicit observation state and serializable value; bounds are represented by integer `x`, `y`, `width`, and `height`. Default attributes are `text` and `desc`; the fixed whitelist is Models-owned. A text request requires a prior public password observation explicitly equal to False; protected or unknown-password text is unavailable and is never read into or serialized as output. Unknown and not-applicable booleans are not invented as False. The existing runtime output-budget/artifact path retains complete safe values when an output is too large to remain inline. The operation retains a bounded 10-second control, normalized safe failures, cancellation, unique resolution, and observation recording policy; it neither changes UI state nor invokes a provider.

Android online and authored execution retain evaluator-backed `assert_with_ai` for explicit pure visual assertions such as appearance, image content, and custom-drawn content lacking accessible semantic state. It is not a visual locator, grounding result, or device action and cannot replace or override a deterministic assertion when the asserted exact text/value/checked/selected state is available through accessibility observation. Locator complexity, ambiguity, or observation failure does not authorize approximation. Schema and Skill guidance express this boundary without pretending a free-form prompt permits a reliable semantic server-side classifier; legitimate pure visual assertions remain callable.

Default-display physical dimensions come only from public `session.device.display_size(control=...) -> DisplaySize` on the owner thread. Successful width and height are actual integers in 1..2147483647; they define physical pointer coordinates in `0..width-1` and `0..height-1`. Context and each coordinate calculation consume current dimensions without caching or assuming an atomic screenshot/observation/action snapshot. The driver never substitutes hierarchy viewport, screenshot geometry, inferred insets, ADB, or private WebDriver state. An absent/incompatible API or failed query is an explicit non-success, not a fallback. Only internal point-based Strict/Replay consumes `reference_screen_size` for proportional scaling; online arguments cannot supply it.

`swipe` validates exactly one Models-owned mode. Untargeted direction preserves the existing 25%-to-75% display gesture. Explicit start/end executes physical coordinates, with internal Strict reference scaling only when supplied. Element mode resolves target/locator uniquely, reads `attributes=("bounds",)` through public inspection, and computes a center-symmetric segment spanning the requested fraction of that element's usable axis; the effective omitted/null fraction is 1.0. For integer half-open bounds the usable endpoints are the first and last interior pixels, the cross-axis point is its integer center, and direction determines endpoint order. Bounds must be positive, fully within the current physical display, and provide at least two usable pixels along the gesture axis; integer rounding that collapses the segment fails. Invalid, missing, ambiguous, off-screen, or degenerate bounds do not fall back to a display gesture. A successful calculation sends exactly one public `device.swipe_between` with the selected duration; it does not prove a slider value or replay the gesture automatically.

`press_key` preserves existing system Home and Back semantics. Case-insensitive `moveend`, `move_end`, and `end` map to KEYCODE_MOVE_END (123); `movehome` and `move_home` map to KEYCODE_MOVE_HOME (122). `Ctrl+End` maps to one public `Device.press_keycode(123, metastate=4096, control=...)` call using Android META_CTRL_ON (0x1000), not a sequence of unmodified events. Unsupported shortcut syntax is rejected without sending a partial key event. Key transport success does not prove application-specific cursor movement.

On first session-requiring operation, the driver lazily binds on its dedicated single-worker thread (`ThreadPoolExecutor(max_workers=1)`), allocates an ephemeral loopback TCP port (`127.0.0.1`), enters `Runtime.start_managed(...)`, and creates an Automation `Session` with `auto_launch=False`, `force_app_launch=False`, `no_reset=True`, `full_reset=False`, and `should_terminate_app=False`.

The private backend constructor accepts `uiautomator2_wait_for_idle_timeout_ms: int | None = None` under the exact built-in integer and Node/Appium-safe range contract owned by `AndroidHarnessSettings`. On owned Session creation, an explicit value is passed unchanged through the SDK public `create_session` keyword of the same name; None omits that keyword and selects no initial idle override. Zero is retained through an explicit non-None check. Ordinary FSQ and SDK defaults remain unchanged; the backend contains no benchmark, Clock, app-id, or task-specific idle selection.

A supplied borrowed Session cannot accept a new non-None initial idle override: construction rejects that combination as a configuration error before any SDK operation, rather than silently ignoring the value or mutating the borrowed Session. Borrowed Sessions with the default None retain their existing behavior.

The SDK owns conversion of the typed keyword to the new-session initial Setting. FSQ does not construct free-form capabilities/Settings payloads, access private SDK state, add a post-create Settings update/readback, or retry Session creation to apply the policy. A missing or incompatible SDK API remains an explicit failure under existing ownership and cleanup rules; there is no TypeError fallback or retry without the keyword.

This initial idle policy does not alter assertion semantic polling, per-inspection OperationControl budgets, capture or unavailable-session guards, error normalization, frozen results, reports, or terminal cleanup. An operation_timeout with response_unknown remains an operational non-success, not target_not_found or a successful assertion; ordinary operations never retry the business assertion or implicitly reconstruct its Session.

`close()` performs explicit terminal cleanup on that same owner thread. An active owned Session uses public `Session.quit()` followed by managed-scope completion. An uncertain or disposing owned Session uses public `Session.dispose(*, control: OperationControl | None = None) -> None`; if quit leaves the Session uncertain, the same close operation may explicitly dispose it. `SessionInfo.state == "disposed"` proves local terminal disposal and settlement of the owned managed service, not an Appium DELETE or confirmed remote Session close; `appium_session_id` remains historical evidence. A public disposal success supplies the managed-service settlement proof without accessing or separately releasing its usage token. Borrowed Sessions are not disposed by this driver.

When `Session.quit()` raises the SDK's `ResourceStateError` with code `session_quit_unknown` and leaves the owned Session uncertain or disposing, explicit `Session.dispose()` can settle that quit uncertainty within the same close flow or a later explicit continuation. Once public disposal succeeds with `SessionInfo.state == "disposed"`, all owned managed-scope obligations complete, and the owner-thread executor shuts down successfully, `close()` returns normally instead of rethrowing the settled quit error. The public disposal contract proves release of the local client and this instance's owned managed process group, streams, and locks; FSQ neither accesses private SDK ownership fields nor infers settlement merely from an absent process. A bounded, secret-safe diagnostic retains the quit error code and request state, `remote_quit_confirmed=false`, and the completed terminal-disposal fact. It is not a capability, replay step, device-restoration claim, or confirmed Appium DELETE.

The driver retains Session, Runtime, connection, managed-scope, and owner-thread resources needed to continue pending cleanup until their corresponding settlement succeeds. Public disposal preflight cancellation or timeout can leave the Session uncertain; disposal that has begun can remain disposing. Both retain ownership and permit a later explicit close to continue the same cleanup through public SDK APIs. Successfully completed stages are not repeated, and the worker is shut down only when pending cleanup no longer requires its owner thread. A successful close means every owned resource is settled; an unsuccessful close preserves pending ownership and reports failure rather than becoming an empty successful close.

Ordinary actions, observations, and context acquisition never dispose, reconnect, or create a new managed generation when a Session is non-active or owned cleanup is pending. They report the unavailable state without changing the SDK's quarantine or sending cleanup signals. Explicit close does not retry business operations, rebuild a Session, restore device state, kill the target app, or stop ADB. SDK terminal disposal is restricted to the exact owned managed connection; foreign or external ownership never grants cleanup authority. The driver consumes public lifecycle states, results, and errors only: it does not inspect private lease/process fields, infer ownership from a port or disk PID, or send process signals itself.

## Python Architecture

- Architecture level: Level 2 Simple Package.
- Dependency direction: depends on Core Interfaces; never imports Harnesses or adapters.
- Rationale: one focused backend implementation is sufficient.

## Error Handling

Text entry returns normalized non-success results with safe diagnostics that distinguish an invalid input target, rejected or mismatched entry, and unavailable verification. Unavailable verification does not assert that the text was not entered. Input values, observed values, target parameter payloads containing input, and raw backend exception messages are not included in text-entry results or diagnostics; comparisons remain in memory. Runtime-secret resolution and execution evidence sensitivity remain owned by Core.

Input failure diagnostics preserve only safe SDK facts: allowlisted `code` as `backend_code`, enumerated `request_state`, bounded allowlisted `completed_steps`, an input-operation stage, and enumerated local `session_state` when publicly available. Literal and runtime-secret values, observed input text, raw SDK messages, request bodies, response fragments, and arbitrary cleanup text are excluded. Pre-inspection failure, write-response uncertainty, and post-verification unavailability remain distinct, and diagnostic collection does not issue device requests or mask cancellation or a primary failure. Local `closed`, `cleanup_pending`, and non-active Session states have distinguishable safe diagnostics; ordinary operations retain quarantine and do not dispose or reconnect. Runner primary action failures and secondary context/capture failures remain independently inspectable.

Primary action/session failures and secondary pending-cleanup failures remain independently inspectable through public exception or normalized runtime-result diagnostics. Pending cleanup failures are not reduced to warnings or hidden by a prior failed operation. The settled `session_quit_unknown` case defined above is diagnostic history, not a remaining cleanup failure; other errors are not swallowed merely because they share the `ResourceStateError` type. Session invalidity is not proof of disposal, and cancellation retains precedence without erasing pending-cleanup diagnostics. Failed disposal, scope completion, or executor shutdown does not clear the ownership needed for explicit continuation, permit implicit reconstruction, or report successful close.

## Verification Scope

Isolated device-free lifecycle verification consumes the real pinned SDK's public terminal-disposal contract and exercises pending ownership, explicit continuation, owned-resource settlement, failure propagation, and cancellation without mocking the lifecycle or usage authority under proof. It makes no device, application, or model calls and does not use or mutate shared SDK records, locks, frozen installations, or historical Run evidence.

Lifecycle verification distinguishes unconfirmed remote quit followed by fully settled disposal and normal idempotent close from disposal, managed-scope, or worker failure that still propagates and retains pending ownership. It proves that settled quit uncertainty remains observable without a false remote DELETE claim, including successful explicit continuation after an earlier failed disposal.

Device-free assertion verification uses the real SDK and Appium client with an isolated protocol peer to establish that unrequested assertion attributes are not fetched, requested predicates still govern consumer-visible results, and target ambiguity, unavailable values, cancellation, and response-unknown failures retain their existing semantics. It preserves SDK-internal reads required by a requested attribute, such as the `checkable` dependency of `checked`; it does not promise one HTTP request per attribute or a fixed device-side latency.

## Current Invariants

- Construction does not connect to a device.
- Compact UI snapshots preserve the documented normalized XML payload and safe fallback.
- Built-in Android context reports Session, current full physical display size from public `Device.display_size()`, backend (`appium_connect_agent`), and current-package metadata from public observations, without private probes. `TreeObservation.viewport` remains content observation metadata only. The optional `current_activity` field remains unavailable and triggers no separate foreground-activity request.
