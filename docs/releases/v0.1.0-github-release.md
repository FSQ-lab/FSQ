# FSQ v0.1.0 - Initial Alpha Release

FSQ is an evidence-first agent harness for AI UI automation. It turns a user-visible goal into an observable Run, captures inspectable evidence, and can turn successful execution facts into a reviewable Case for deterministic replay.

This first release is an alpha for evaluation, feedback, and early contribution.

## Install

```bash
python -m pip install fsq-agent
```

The base package includes the Python dependencies for all supported platforms. FSQ does not install browsers, applications, devices, ADB, Appium services, or other host prerequisites during `init`.

## What is included

- AI-driven UI exploration from a natural-language goal.
- Deterministic YAML Case replay through `fsq case test`.
- Run-local suggestions and optional candidate Cases through `fsq case test --suggest`.
- Evidence capture with screenshots, UI snapshots, events, metadata, and reports.
- `fsq doctor` readiness checks for Workspace, platform target, Provider, and execution capability.
- `fsq runs list`, `fsq runs show`, `fsq runs logs`, and offline static HTML reports.
- Local Control Plane through `fsq ui`.
- User-level Provider configuration shared by CLI and UI.
- GitHub Copilot and Azure OpenAI Provider support.

## Platform support

FSQ complements platform automation backends rather than replacing them:

| Platform | Backend | Host prerequisite |
|---|---|---|
| Web | Playwright | Installed Chromium-family browser |
| Android | uiautomator2 | ADB and an online authorized device |
| Windows | pywinauto | Windows and an existing application |
| macOS | Appium Mac2 | macOS, an existing application, and a reachable Appium service |

## Start here

```bash
mkdir fsq-web-demo
cd fsq-web-demo
fsq init --platform web --browser-channel chrome
fsq doctor
```

Then follow the README quickstart or run the public deterministic Web example in `examples/web/example-domain.fsq.yaml`.

## Alpha scope and known limitations

- Public CLI, Case DSL, Provider, and UI details may evolve before 1.0.
- Provider-backed commands require GitHub Copilot or Azure OpenAI configuration.
- `case test --suggest` executes the source Case once, then analyzes persisted Case, report, and evidence; it must not operate the UI again.
- Platform readiness depends on host applications, devices, browsers, ADB, and Appium services being available outside FSQ.
- Evidence quality depends on the target UI and the selected platform backend.
- Final publication requires the configured CI and release workflow checks to pass for the release commit and verified distribution artifacts.

## Privacy and evidence sharing

FSQ stores UI screenshots, UI trees, logs, metadata, reports, suggestions, and candidate Cases locally. These artifacts can contain application data.

Before sharing any issue, pull request, demo, report, or Run artifact, review and redact credentials, tokens, API keys, authorization headers, cookies, device codes, account data, private URLs, device serial numbers, local paths, and private UI content.
