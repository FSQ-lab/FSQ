# FSQ v0.3.1 release preparation

Date: 2026-10-20. Python distribution: `fsq-agent` 0.3.1. FSQ remains alpha.
This record prepares the release; it does not claim a merged PR, existing
`v0.3.1` tag, GitHub release, or PyPI publication.

## Changes

- Standalone `fsq quick-test context` discovers readiness and target choices;
  `fsq quick-test run` executes one Explore goal without an HTTP service or
  project Workspace setup. Android, Web, Windows, and macOS retain their
  existing host/runtime restrictions and external prerequisites. Execution uses
  the dedicated Quick Test Workspace and shared user-level Provider settings.
- Web-only `--url` accepts an exact HTTP(S) starting address separately from
  `--goal`. The address retains its original spelling, escapes, port, path,
  query, fragment, and punctuation. Invalid or unsafe input fails before
  inference or mutation. Existing goal-only address identification and
  address-free Web search remain supported; browser Quick Test keeps its
  existing single goal field.
- Web goal parsing handles adjacent Chinese punctuation, paired Chinese and
  fullwidth wrappers, address labels such as `网址:` and `URL:`, and Markdown
  link/strong-emphasis boundaries. Complete-reference checks preserve address
  data and reject malformed, ambiguous, embedded, or substituted references.
  Frozen starting-address context now reaches dynamic Web planning/execution
  so the first navigation receives the exact absolute address.
- The host-neutral FSQ Agent Skill defaults to Quick Test. It streams actual
  progress, interrupts the same process for cancellation, and reports the
  authoritative whole-goal verdict with available evidence. Lost output or a
  cancellation request alone does not prove completion; the Skill does not
  automatically resubmit. Candidates stay Run-local without Case publication.
  Explicit Case creation and strict replay remain available, as does the
  provider-free Web troubleshooting Case. The separate Codex compatibility
  integration retains its existing workflow.
- The bilingual README presents Coding Agent and `fsq ui` entry paths. The
  Python distribution version advances to 0.3.1; the private npm package keeps
  its independent 0.1.0 version. No dependency or frontend version change is
  part of this release metadata update.

## Upgrade after publication

Once 0.3.1 is published, upgrade the Python environment used by FSQ:

```bash
python -m pip install --upgrade fsq-agent==0.3.1
```

Copied project Skills do not update when the Python package is upgraded. From
the user project directory, explicitly refresh the copy:

```bash
fsq init --agent skill
```

Review the installer's update/backups under `.agents/skills/fsq/`, then start a
new Coding Agent session or reload Skill discovery. `--no-overwrite` preserves
an existing copy. No Workspace reinitialization or Provider reconfiguration
is required solely for this upgrade.

For a known Web starting address, select an available browser reported by
context and pass the address separately:

```bash
fsq quick-test context --platform web
fsq --output jsonl --non-interactive quick-test run --platform web --target-id chrome --url 'https://example.com/search?q=FSQ#results' --goal "Verify the results contain FSQ"
```

Goal-only commands without `--url` remain valid. `fsq ui` remains the browser
entry for Quick Test and FSQ Case Manager. See the [CLI reference](../cli-reference.md)
for command forms, exit codes, target selection, and Case workflows.

## Validation scope and release status

Prior functional QA reported **4,699 Python tests passed and 11 skipped**,
with the real-browser module explicitly excluded at the user's request, plus
**153 frontend tests passed** and a successful frontend typecheck. The prior
functional review passed. The user also reported manual Web and Coding Agent
testing; this is not all-platform live execution evidence. Controlled test
collaborators do not establish live device, browser, model, or host behavior
across all four platforms.

This bounded metadata update is checked with the existing distribution
contract module, including a failing version assertion before the metadata
change and a passing run after it. Final package build/installed-artifact
verification and independent release review remain integration checks. CI for
the final release snapshot is pending; the earlier local results do not claim
a completed release pipeline. Merge, tag creation, GitHub release creation,
and PyPI publication are separate actions outside this preparation.
