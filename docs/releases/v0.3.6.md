# FSQ v0.3.6 release preparation

Date: 2026-11-20. Python distribution: `fsq-agent` 0.3.6. FSQ remains alpha.
This document prepares a release identity and notes; it does not establish a
`v0.3.6` tag, GitHub release, PyPI publication, or deployed Website revision.

## Changes since the 0.3.5 release

- [Windows Quick Test common application catalogue (#66)](https://github.com/FSQ-lab/FSQ/pull/66):
  added `fsq_agent/config/applications.windows.yaml` with stable catalogue
  entries for `edge`, `chrome`, `edge-beta`, `edge-canary`, `notepad`, and
  `calculator`, resolving installed executable paths and optional
  `window_title_re` constraints through existing Quick Test intent analysis
  while preserving explicit-path precedence and failing explicitly when a
  selected preset is unavailable.
- [Windows driver `app_path` target identity binding and owned cleanup (#27)](https://github.com/FSQ-lab/FSQ/issues/27):
  hardened `PywinautoWindowsDriver` so configured `app_path` targets never fall
  back to unverified `connect(active_only=True)` or unconstrained global
  `title_re` matches across unrelated executables. Launch snapshots pre-existing
  top-level window handles (including minimized/offscreen windows) and running
  process IDs, prefers newly created target windows across Chromium/Edge
  single-instance multi-PID handoff (plus post-launch `ApplicationFrameHost.exe`
  frames when `window_title_re` is configured), keeps live observation/action
  resolution anchored across OS focus changes, and restricts `killApp` /
  `close()` to terminating owned processes or closing only newly created handoff
  window handles while surfacing disposal failures explicitly.
- Python metadata and its exact distribution-contract assertion advance to
  0.3.6. The private npm package retains its independent 0.1.0 version.

These changes are established by repository history following the `v0.3.5`
release. The comparison references below anticipate the `v0.3.6` release tag
rather than claiming that `0.3.6` has already been tagged or published.

## Upgrade after publication

Once 0.3.6 is published and obtainable from the package index used by your
Python environment, upgrade with:

```bash
python -m pip install --upgrade fsq-agent==0.3.6
```

Project-local Skills are copies. Package installation or a host reload alone
does not refresh them. From your Coding Agent project, explicitly run:

```bash
fsq init --agent skill
```

Review installer updates, backups, and conflicts under `.agents/skills/fsq/`,
then reload Skill discovery or start a new Coding Agent session.
`--no-overwrite` preserves an existing copy. Existing Android, Web, Windows,
macOS, and iOS Workspaces and Provider configurations require no
reinitialization solely for this version change.

Continue through either [Coding Agent or FSQ UI](../getting-started.md).
Quick Test uses the dedicated user-level Workspace, returns inspectable
results/evidence, and does not save a formal Case or automatically replay one.
Python 3.11+, a configured supported Provider and selected model, and
[platform-specific prerequisites](../platform-prerequisites.md) still apply.
Never paste Provider credentials into Coding Agent chat.

## Validation and publication status

The preparation uses a failing exact-version contract check before the metadata
bump, followed by the focused distribution-contract and Windows harness/catalogue
suites, Ruff lint/format, and diff checks. Results belong to the final
identified source snapshot and its external validation evidence; these
instructions do not assert a passing result. Earlier PR, release, or local
results are historical and are not final 0.3.6 validation evidence.

Final frontend compilation, wheel and sdist creation, a wheel rebuilt from the
sdist, metadata/resource comparisons, fresh source-free installed-package smoke
tests, and CI matrix verification run in repository automation. The smoke must
use the built artifact outside the source checkout, including both console entry
points, platform presets, copied Skill resources, and packaged static serving.
These checks do not replace a real target or Provider test.

The complete 0.3.6 Python/frontend CI and supported-platform matrix are pending.
No all-platform live execution, clean public-index end-to-end first-use run, or
successful release pipeline is claimed. Building a local wheel does not prove
public installation availability.

[Media provenance](../media/quick-test-demo-provenance.md) records the matching
Android Run's producer as FSQ 0.2.1; it is not a recording of 0.3.6. Source
commit, capture/export timestamps, and some runtime conditions remain
unestablished. The [media acceptance record](../media/media-acceptance.md)
separately retains whole-video privacy/security, complete caption
synchronization and muted comprehension, three-person new-user acceptance,
public first-use, and deployed canonical-page verification limits.
Selected-image review is not full-video privacy clearance. Evidence may contain
private application data; review it before sharing. These publication checks are
not satisfied by a version bump, unit test, or build.

No tag creation, workflow dispatch, GitHub release, PyPI upload, or deployment
is performed by this preparation. Publication requires a separate authorized
release action and its existing manual verification/environment prerequisites.
