# Module: drivers.ios

## Purpose
Implement iOS mobile automation through the `appium-connect-agent` Python public library (`appium_connect_agent` backend), including lazy thread-affine managed loopback Appium server and XCUITest `Session` lifecycle, explicit application lifecycle, touch/keyboard/button/alert actions, compact semantic observations, visual inspection and assertions, and safe failure normalization.

## Dependencies
- `core.interfaces.IOSDriverInterface`, `capabilities`, and iOS parameter/result models.
- Optional `appium-connect-agent` (`appium_connect_agent.contracts`, `appium_connect_agent.runtime`, `appium_connect_agent.automation`), imported lazily at runtime without direct `Appium-Python-Client`, `selenium`, or private WebDriver access.

## Public Interface
Instances satisfy `IOSDriverInterface`; the concrete backend class is private outside Drivers and composition.

`ui_snapshot`/`uiSnapshot` returns the bounded compact current XCUITest hierarchy as `xml`, without a duplicate `root` dictionary. It retains `coverage`, `compaction`, `device_local_time`, logical `viewport` when available, and existing source metadata. `IOSUiSnapshotParams.include_offscreen` defaults to `false`. `inspect_element`/`inspectElement` returns unclipped structured element attributes while withholding `value` on `XCUIElementTypeSecureTextField`.

`tap_at`/`tapAt` takes `{"point": {"x": <int>, "y": <int>}}` in current viewport logical points and dispatches resolved coordinates through public `Device.tap_at`, not the Mac2-only `Device.click_at`.

`input_text`/`inputText` and `clear_text`/`clearText` require a uniquely resolved editable XCUITest control (`TextField`, `SecureTextField`, `SearchField`, `TextView`, or `ComboBox`) with explicit `enabled=True` and `displayed=True` before mutation. The driver binds by `type` and `UID` when a nonempty `uid` is readable, otherwise by `type` and `name` when a nonempty accessibility `id` is readable, and verifies the type and every available nonempty identifier before mutation. An SDK that rejects the `uid` attribute before sending an inspection is supported by retrying the read without `uid`. Without either identifier, the driver retains a text-independent locator or binds a mutable locator using exact `type` and `rect` coordinates. It does not redirect writes when that rectangle stops resolving. If a rectangle-only anchor is definitively missing after a write, the driver may inspect a unique focused control of the original type for readback only; an enabled but unfocused control is insufficient.

For nonempty `TextView` input, the driver reads the prior text clipboard when possible, stages the submitted text through public SDK clipboard APIs, long-presses the bound element for 600 ms, and clicks the uniquely resolved native `Paste` item. It attempts to restore known prior clipboard text even on failure after staging. Missing or ambiguous Paste items and definitive `not_sent`/`response_received` failures permit fallback to `Element.send_keys`, which can fall back once to `Element.send_macos_keys` on those same definitive request states while the session remains active. Unknown mutation outcomes, including `response_unknown` from Paste, return an `action_error` asking for readback without resending text. Clipboard contents are not included in diagnostics.

Post-write verification checks type and enabled state, verifies preserved accessibility ID and any available pre/post UID, and does not reject geometry changes by themselves. For non-secure controls, clear/empty readback accounts for XCUITest placeholder exposure. Nonempty replacement verifies the submitted text; append also accepts insertion into existing content. Matching permits common typographic/line-ending normalization and numerically equivalent currency/thousands formatting for strictly numeric inputs and readbacks, not unrelated text. Secure text fields withhold value readback and verify structural identity and enabled state only.

`swipe` supports mutually exclusive full-screen direction, explicit logical points, and element-direction modes over `Device.display_size()` logical points. Untargeted directional swipes compute safe interior logical coordinates within 20%–80% vertically and 18%–82% horizontally via `Device.swipe_between(...)`. Element-scoped directional swipes inspect `bounds`, require positive logical bounds inside the current display, compute bounded center-symmetric span endpoints with horizontal edge insets, and execute `Device.swipe_between(...)` rather than unvalidated full-element backend swipes.

## Internal Structure
- Private `AppiumConnectIOSDriver` backend implementation (`_appium_connect.py`), decorated with `@_ios_driver_tool(...)` bound to `IOS_ACTION_DEFINITIONS`.
- Thread-affine execution worker (`ThreadPoolExecutor(max_workers=1)`) keeping `Runtime.start_managed(...)`, `create_xcuitest_session(...)`, `Session.ensure_alive(...)`, `Session`/`Element`/`Device` calls, and `close()` on one owner thread.
- Lazy managed Appium loopback server + XCUITest session lifecycle: construction is lazy and rejects non-`None` initial-Session WDA policy overrides (`xcuitest_wait_for_idle_timeout_seconds`, `xcuitest_snapshot_max_depth`, `xcuitest_accessibility_deadline_seconds`, `xcuitest_animation_cool_off_timeout_seconds`, `xcuitest_page_source_excluded_attributes`) when a borrowed `Session` is supplied; `ensure_session` resolves explicit or auto-selected single device UDID, honors Simulator `bundle_id` / `.app` or real-device `bundle_id` / `.ipa` with WDA code-signing parameters, forwards configured initial-Session WDA policies and `new_command_timeout_seconds` (default `900.0`) to `create_xcuitest_session(...)` (preserving them on explicit `launchApp(new_session=true)` replacement), and scales observation/locator operation timeouts safely with `action_timeout_seconds` and any configured `xcuitest_accessibility_deadline_seconds`. The animation cool-off policy is passed as the SDK's `xcuitest_animation_cool_off_timeout_seconds` keyword, including `None` to select no override; it does not change FSQ operation timeouts.
- The private driver accepts `xcuitest_page_source_excluded_attributes: Sequence[str] | None` and validates it through `IOSHarnessSettings` (only list or tuple input is accepted when configured). For both initial and replacement owned Sessions, it omits the SDK keyword when unset and passes the normalized tuple when configured. Configured exclusions require an SDK supporting the keyword to set WDA's `appium:settings[pageSourceExcludedAttributes]`; they are not silently dropped or applied as a post-creation update. Excluding native `visible` and `accessible` does not disable SDK-derived viewport visibility when bounds and viewport are available.
- Structured locator adapter translating `IOSLocator` (`accessibility_id`, `id`, `name`, `label`, `value`, `element_type`, `predicate`, `class_chain`, `xpath`) into `Session.element(...)` with `Element.inspect(...)` uniqueness and ambiguity reporting.
- WDA predicates address the target element's own attributes; `descendants` attribute references in predicate strings or class-chain predicate blocks fail with `ConfigurationError` and `resolution_reason="invalid_locator"` before a locator query. Use class-chain path segments or XPath for hierarchy. Additional class-chain predicate constraints precede a terminal position selector (`[N]`, `[-1]`, `[*]`); an explicit matching terminal class already satisfies `element_type`.
- Compact `<XCUIElementType*>` snapshot builder with `node_count`, text clipped to 160 characters, interactive-node preservation within the retained scope, depth bounding, and a safe unparsed fallback.
- Before normal layout/depth compaction, the default snapshot prunes bottom-up. Remove leaves explicitly marked `visible="false"` and non-interactive leaves with an explicitly non-positive width or height and no semantic text or identifier signal. Do not infer invalid geometry from missing or malformed dimensions. Preserve the application root and ancestors of retained descendants. `compaction.offscreen_nodes_omitted` counts both kinds of pruning, separately from layout/depth omissions, and a positive count sets `coverage.status` to `"partial"`. `include_offscreen: true` skips both kinds; empty and uncompacted fallback results report zero off-screen pruning omissions.
- Consumes package-internal `drivers._visual_inspection` for public-SDK visual provider adaptation (`inspectWithAI`), same-frame evidence handoff, and safe observation results without host coordinate mapping.

## Python Architecture
- Architecture level: Level 2 Simple Package.
- Dependency direction: depends on Core Interfaces, `capabilities`, and `models`; never imports Harnesses, sibling platform driver subpackages, or adapters.
- Rationale: one focused XCUITest backend implementation is sufficient.

## Error Handling
Normalized action/result and failure-category envelopes remain intact. Safe structured resolution reasons distinguish `not_found`, `ambiguous`, `invalid_locator`, `session_unavailable`, and `backend_error`; `TargetError` is mapped as definitive `not_found`/`ambiguous` only when `request_state != "response_unknown"` and the local `SessionInfo.state` is `"active"`. Backend diagnostics expose only allowlisted SDK `backend_code`, enumerated `request_state`, 32-lowercase-hex `operation_id`, allowlisted `completed_steps`, and local `session_state`. When safely attributable, ambiguity diagnostics include up to five candidates with structural type/bounds and nonempty `name`, `label`, and non-secure `value` capped at the snapshot text limit. Secure text values, untrusted backend diagnostics, submitted text, runtime secrets, and device or signing secrets are not exposed. Unknown outcomes do not trigger additional candidate observations.

## Current Invariants
- Construction and registry discovery do not import `appium_connect_agent`, start Appium, query `simctl`, or launch an application.
- All `Runtime` and `Session` operations execute on one driver-owned single-worker thread to satisfy `appium-connect-agent` owner-thread affinity; idle liveness checks use public `Session.ensure_alive(...)` before action execution.
- Non-active owned sessions and drivers with `_cleanup_pending` or `_closed` state fail fast with safe `session_unavailable`/`cleanup_pending`/`closed` diagnostics and never implicitly close or reconstruct a session during ordinary tool, observation, or context calls; only explicit `launchApp(new_session=true)` on an active owned session replaces the session.
- Progressive startup ownership retains `_runtime`, `_managed_scope`, `_connection`, and any `exc.session` attached to a failed `create_xcuitest_session(...)` call (cleaning up `service_port_in_use` attempts via `Runtime.cleanup_managed(...)`) so a subsequent explicit `close()` can complete terminal `Session.dispose(...)` and managed-scope settlement on the owner thread while retaining safe `session_quit_unknown` settlement diagnostics.
