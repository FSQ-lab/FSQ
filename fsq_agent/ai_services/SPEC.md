# Module: ai_services

## Purpose

Own FSQ visual assertion/inspection, completed-Case suggestion, and Quick Test intent analysis over neutral model calls. Services prepare inputs, supply private strict output schemas/parsers, and convert validated objects into FSQ results. They do not own supplier authentication, SDK objects, platform capture/coordinate conversion, installed-application discovery, persistence, platform actions, Case execution, candidate publication, or reports.

## Dependencies

- `models`: `AIAssertionRequest`, `AIAssertionResult`, and `ConfigurationError`.
- `config`: resolved `Settings` for service construction.
- `providers`: public configured-session factory and supplier metadata/lifecycle access.
- `agent_engine`: neutral text/image requests, generic output contracts/results, and safe model errors.
- Pydantic for private model-facing output schemas and strict business validation.
- Standard library file reading, MIME detection, JSON, timing, and immutable records.
- No dependencies on Core, Agent, adapters, execution, Application, or SDK packages. Core accepts an injected evaluator structurally and does not construct these services.

## Public Interface

- `AIAssertionEvaluator`: synchronous `evaluate(request: AIAssertionRequest, *, cancellation_check=None) -> AIAssertionResult` and `close()` operations, with an optional trusted cooperative cancellation collaborator for Android, iOS, and macOS scoped visual evaluation. The serializable request contains no live callbacks or SDK objects.
- `AIAssertionEvaluator.inspect(request: AIVisualInspectionRequest, *, cancellation_check=None) -> AIVisualInspectionResult` implements a separate observation-only protocol using the same configured model-session lifecycle and reasoning effort, without new constructor/factory/resolver parameters. A private implementation owns its strict summary/image-bounds schema. It validates authorized current-frame input, requested mode/region/candidate bounds and budget, performs at most one tool-free `Model.complete` request using `ImageContent` and a Pydantic output contract, and rejects invalid/refused/late output without repair/retries. Extract has no candidates; locate image bounds use full-image coordinates, never model-generated pointer coordinates. SDK adapter code constructs physical pointer results. Cancellation and primary/cleanup precedence are preserved; errors remain safe neutral engine failures, not assertion verdicts.
- `CaseSuggestionAnalyzer`: synchronous `analyze(*, parsed_case, execution_report) -> CaseSuggestionAnalysis` over completed execution facts.
- `CaseSuggestionAnalysis`: immutable summary, suggestion entries, and optional candidate Case YAML.
- `build_ai_assertion_evaluator(settings)` and `build_case_suggestion_analyzer(settings)`: create services from the selected supplier without inference.
- `check_case_suggestion_readiness(settings)`: safely constructs and closes a configured analyzer without inference or UI actions.
- Quick Test intent analysis: a synchronous public analyzer and configured factory interpret the current goal and selected platform into an immutable sufficiency decision, safe reason, and application lookup reference, including a typed inferred native identity when determinable. The result also distinguishes a clear Web search/discovery intent from a known-site objective; this is an internal semantic distinction, not a new user-facing mode. The factory requires only the saved Provider and selected-platform inference policy, not a runnable application target or registered Workspace; it performs no inference during construction.
- Windows intent analysis accepts a caller-supplied catalogue summary of existing IDs, names, and descriptions. The existing single tool-free intent-analysis request also returns optional `app_config_id`: semantic selection of a supplied ID or null for no-match, not literal keyword/alias routing. Paths, window/process inventories, and credentials are not selection context; no additional inference call is made.
- A non-null `app_config_id` must be a real supplied catalogue ID. Invented IDs, malformed output, model failure, and ambiguous application intent are not no-match. Explicit executable references retain their existing provenance checks and take priority over catalogue selection. Without an explicit path, a selected ID does not use a competing inferred path; null retains existing inferred-identity/name lookup behavior.
- `QuickTestIntent` carries the optional ID only as an intent result. Application resolves and validates the selected configuration locally; the model does not certify availability. Existing sufficiency checks, Provider policy, and other-platform intent behavior remain unchanged.
- `QuickTestWebAddressParser`: a public deterministic, tool-free parser used by Application and Quick Test provenance checking. `validate(address) -> str` validates one entire explicit HTTP(S) address and returns the unchanged text, without natural-language extraction; `extract(goal) -> tuple[str, ...]` returns ordered deduplicated exact HTTP(S) references; `contains(goal, reference) -> bool` accepts only a complete extracted reference. Invalid supplied navigation syntax or unresolved enclosing boundaries raises `ValueError`; provenance checks convert invalid input into the existing safe neutral output error. Parser construction and use require no Provider, Workspace, host discovery, or inference.

Service constructors accept a keyword-only `reasoning_effort: ReasoningEffort = "mid"` option while preserving existing assertion/suggestion constructor arguments. The factories pass the resolved selected-platform reasoning effort; direct callers that omit it remain supported. Each evaluation/analysis places that neutral value in its `ModelRequest`, without selecting a native enum or relying on SDK/server defaults.

The stable services, factories/readiness helper, and immutable service results are exported from `__init__.py`. Their callers are Application and entry/runtime composition; they are not supplier infrastructure exports. Service-specific output facts are local records; shared assertion request/result contracts remain in `models`.

## Model-Facing Output Contracts

Each service supplies an `OutputContract` built from its private Pydantic output model's JSON Schema and parser. Root schemas are objects, every declared field is required, and nullable fields are present with `null` when absent. Root objects and nested output records forbid additional properties. Field validation is strict: booleans and text are not obtained through coercion. The parser validates the whole JSON document, allowing ordinary JSON whitespace but not Markdown fences, surrounding prose, extracted substrings, non-finite numeric extensions, or non-object roots. Services consume only the expected typed `parsed_output`; a missing or wrong parsed object is `invalid_output`, not permission to parse result text again.

- Web and Windows visual output retains only `passed`, `explanation`, and `confidence`, with its existing strict validation. Android, iOS, and macOS visual output instead contains only `outcome=passed|failed|inconclusive`, nonblank explanation, and required nullable finite confidence in 0..1. Inconclusive is a valid uncertain model observation, never a false boolean verdict. Host-owned reason, conflict, identity, usage, timing, capture, and authorization facts are not model-supplied output fields. Strict whole-document parsing rejects prose, fences, non-finite numbers, unknown fields, and missing nullable fields without repair or fallback parsing.
- Case suggestion output contains only `summary`, `suggestions`, and `candidate_case_yaml`. `summary` is a nonblank string normalized by stripping surrounding whitespace. `suggestions` is a possibly empty array of objects containing only required nonblank string `kind` and `message` fields, also stripped of surrounding whitespace; kinds are not a closed enum. `candidate_case_yaml` is null or a nonblank string normalized by stripping surrounding whitespace, without another YAML formatter. Conversion returns the frozen `CaseSuggestionAnalysis` and immutable suggestion entries. A candidate string is not proof of valid FSQ YAML or successful execution; Application and Case DSL own validation and publication.
- Quick Test output distinguishes a sufficient test intent from an insufficient one and supplies only bounded application lookup information and a safe explanation. It does not invent actions, expectations, or an application absent from the current goal. A short but actionable goal is not rejected for length; naming only an application or topic is not sufficient to invent a smoke test. Explicit identity/URL provenance is checked against the supplied prompt, not accepted merely because the model labels it explicit. For a named native application, the model may derive its package, bundle, or executable identity even when that technical value is not written in the prompt; it remains typed inferred provenance and can scope subsequent platform lookup. An unresolved or ambiguous interpretation cannot become a positive determination merely to fill that field. The model does not verify installed display names, installation, or readiness. The result is not an execution plan, permission to launch without validation, or a test verdict.
  A clearly scoped request to view, inspect, browse, or explore the identified application is actionable intent even without a rigid QA assertion: its checkable outcome is delivery of truthful observations from that authorized flow. The analyzer does not demand an invented expected state or known answer, while an application/topic alone or unresolved application scope remains insufficient.
- A Web search/discovery objective may be sufficient without a site URL or a known answer. Its search subject is grounded in the current goal, including ordinary Chinese text; the analyzer does not supply the final website address from memory. For the address-free path, `explicit_reference` and native `inferred_hint` remain absent. Insufficient search intent is still rejected, and a supplied invalid address cannot be ignored to obtain a positive search classification. Existing native target interpretation and explicit-reference provenance remain unchanged.

Web-reference extraction and model-reference checking use the same parser and boundary decisions. ASCII/Chinese paired quotes, inline code, angle brackets, and Markdown link destinations establish explicit address boundaries and preserve their enclosed address bytes as text, including legitimate trailing punctuation. Markdown labels, optional link titles, and surrounding sentence punctuation are not navigation addresses. Nested balanced ASCII parentheses in paths and balanced IPv6 authority brackets remain inside the address; unmatched/malformed pairs fail rather than producing a prefix address. IPv6 authorities retain brackets and optional valid ports. Ports must be in 1..65535 when supplied, and a nonempty host, valid bracketed authority, no userinfo/backslash/control characters, and supported HTTP(S) scheme are required. Malformed percent escapes are rejected rather than decoded or repaired.

For bare addresses, whitespace and natural-language delimiters bound the reference. Chinese sentence separators and external closing quotes/brackets delimit adjacent prose; literal occurrences of those ambiguous punctuation characters inside a URL require explicit quoting or percent encoding. ASCII punctuation in a valid path/query/fragment, including terminal `.`, `?`, `;`, `!`, and commas, is preserved rather than processed with general `rstrip`. Unseparated ambiguous prose or delimiters that cannot be resolved safely fail instead of silently shortening or extending the address. Explicitly delimited Unicode paths/query values remain unchanged. Exact scheme/host case, percent escapes, empty query/fragment delimiters, and address order are preserved. Complete-address provenance rejects model-normalized or truncated paths, parameters, ports, fragments, prefix hosts, scheme-like prefixes, and an inner URL embedded in another address. Unsupported or malformed supplied schemes do not become an address-free search.





Quick Test intent analysis accepts an optional explicit Web starting URL supplied separately from the goal. It uses the parser's complete-address validation before inference, includes the explicit target as structured input for test-intent assessment, and preserves the caller-supplied address as the selected starting reference. No model echo, normalization, or reconstructed address replaces that target. A valid explicit URL supplies application context but does not make an actionless goal sufficient, prove readiness, or authorize an alternate target. Goal text may describe subsequent navigation; it is not used to re-extract or override the explicit starting URL. Without that separate value, existing goal extraction, model-reference provenance, and address-free search remain unchanged.

A Chinese fullwidth opening parenthesis immediately after a bare address introduces an explanatory passage ending at its matching fullwidth closing parenthesis. The parser excludes that passage from the URL and preserves it in the original goal. Nested fullwidth parentheses may occur within the explanation. Missing/mismatched enclosing marks or URL-like continuation directly after a closing mark fail rather than yielding a shortened or substituted address. Parenthesis characters inside an explicitly delimited URL remain original address data.

Chinese wrapper handling recognizes paired `（）`, `［］`, `【】`, `《》`, `〈〉`, `「」`, `『』`, `“”`, `‘’`, and fullwidth symmetric quotes `＂＂`/`＇＇`. Complete enclosing pairs establish an exact reference boundary; malformed, mismatched, or missing pairs do not authorize a shortened reference. Opening marks from those pairs immediately after a bare reference delimit subsequent prose just as closing marks do. Chinese ellipsis `…` (including `……`) and em dash `—` (including `——`) likewise delimit adjacent prose outside explicit enclosures. These characters inside a clearly enclosed path/query/fragment remain original URL data. Existing ASCII balanced URL parentheses and bracketed IPv6 authorities retain their existing semantics.

Markdown strong-emphasis forms `**URL**` and `__URL__` are recognized as complete presentation wrappers, including when the address uses an existing quote/angle/inline-code wrapper. Markers and surrounding prose are excluded from the extracted reference. Asterisks or underscores inside an explicitly enclosed address remain URL data; unmatched or ambiguous emphasis must not yield a prefix address. Existing Markdown link destination, label/title exclusion, escaped-title handling, and exact-address rules remain shared with provenance checking.

At a natural-language token boundary, the labels `URL`, `URI`, `网址`, `地址`, `链接`, `目标网址`, `目标地址`, and `网站地址` followed by one ASCII or fullwidth colon may introduce an address directly, with optional whitespace. ASCII labels are case-insensitive. This label handling applies before complete supplied-navigation validation and does not recognize an arbitrary URI scheme as a label. In particular, `file:https://…`, `javascript:https://…`, unknown scheme-like prefixes, embedded URL query values, and identifier-prefixed URLs remain rejected or remain part of their complete outer address. Fullwidth colon inside the supplied URL scheme/authority is never silently converted into ASCII.

## Internal Structure

- `__init__.py`: public service, factory, result, and readiness exports.
- `_factory.py`: configured service construction and safe suggestion readiness.
- `_ai_assertion.py`: private assertion output model/schema/parser, screenshot/text input preparation, prompting, timing, and parsed-verdict result construction.
- `_visual_inspection.py`: private strict observation output/schema/parser and neutral model-request/evaluation implementation; no SDK import or coordinate mapping.
- `_case_suggestion.py`: private suggestion output models/schema/parser, read-only completed-Case prompting, and immutable service result conversion.
- `_quick_test.py`: private intent/inferred-hint output schemas, language-aware provenance parser, and the exported `QuickTestIntentAnalyzer` and immutable `QuickTestIntent` (including its typed `inferred_hint`); `_factory.py` exports `build_quick_test_intent_analyzer`.
- `_web_addresses.py`: private implementation of the exported `QuickTestWebAddressParser`; owns deterministic Web boundaries, syntax validation, and complete-reference comparison shared by intent analysis and Application.

## Python Architecture

- Architecture level: Level 2 Simple Package.
- Public API: stable services, their factories/readiness, and service-specific result.
- Internal modules: `_*.py` files are private.
- Domain boundaries: FSQ assertion, suggestion, and Quick Test intent policy only; model invocation delegates downward.
- Boundary models: private Pydantic model-facing outputs, shared FSQ assertion models, immutable service results, and neutral engine request/results. Private output models remain in their owning service modules and are not exported or placed in a shared business-schema catalog.
- Dependency direction: business callers consume services; services consume public providers/engine APIs; neither providers nor engine depends back on services.
- Rationale: focused inference services share configured model access without another service registry or persistence layer.

## Error Handling

Web and Windows assertions retain missing-configuration exceptions, valid positive/negative verdicts, and safe `status="error", passed=False` generation/validation failures; the false boolean is not a negative evaluation. Android, iOS, and macOS failures map to an inconclusive outcome with an allowlisted reason: unavailable configuration, authentication, rate limiting, refusal, provider timeout, unknown in-flight completion, invalid output, and input/capture/privacy/budget failures never become assertion failure. Safe neutral engine category/reason metadata is retained without copying raw response, exception, parser, credential, or SDK content.

Case suggestions propagate neutral generation/validation failures instead of converting malformed model output into a configuration error or a successful empty analysis. Application retains `case.suggestion_failed`, completed Run/report truth, and candidate publication authority without expanded HTTP/CLI result fields. The neutral cause remains in the service/error chain.

Quick Test propagates neutral inference/output failures separately from a valid insufficient-intent result. Application owns the public error category and termination policy. Analysis cannot ask a follow-up question, repair rejected output with another inference, change Provider settings, inspect the host, or launch an application. It receives only the current goal, selected platform, and necessary locally filtered lookup metadata, not previous goals, workspace secrets, or complete installed-app inventories.

Scoped resources close on every path. Cleanup does not mask a primary failure or cancellation, including a failure already represented as an inconclusive/error result; cleanup-only failures remain independently visible. Explicit cancellation and interruption propagate rather than becoming business verdicts. There is no semantic retry, provider fallback, JSON repair, or detached inference accepted as a late verdict.

## Current Invariants

- Each evaluation/analysis makes at most one tool-free `Model.complete` request with a caller-owned output contract through the configured provider session, with no semantic retry, JSON repair, free-text fallback, Runner, action tool, handoff, or implicit Provider configuration change. Android, iOS, and macOS input/privacy/deterministic gates may reject before any inference.
- Visual assertions and Case suggestions use the same resolved platform reasoning-effort policy as the Coding Agent business phases. Services retain their construction-time effort value, do not refresh it mid-task, and do not add automatic effort tuning, a native mapping, or a retry loop. Explicit low connection testing remains owned by Providers and does not alter service policy.
- Assertions use the selected provider/model without a separate override. Web and Windows screenshot preparation and text-only behavior remain unchanged. Android, iOS, and macOS require a current, validated, Run-contained capture and trusted authorization; they never fall back to text-only evaluation or historical image/digest reuse.
- Android, iOS, and macOS evaluation checks declared surface/region, upload/privacy policy, encoded/decoded image budgets, PNG single-frame validity, monotonic freshness, and capture identity before external processing. Defaults and hard bounds are Models-owned. At most one active evaluation is permitted per evaluator; exceeding concurrency or input bounds is `budget_exceeded`. A provider timeout is inconclusive; cancellation remains cancellation, and a response observed after the deadline is discarded without retry.
- Android, iOS, and macOS deterministic adjudication compares only host-produced same-target exact property/value facts against structured expectations; unknown, not-applicable, clipped, stale, or unrelated facts are not counterevidence. Contradictory deterministic evidence forces `failed` and marks `deterministic_conflict`, even for model passed. A valid model failed remains failed when deterministic facts support the expectation, but the conflict is exposed. Exact accessible semantics are not delegated to visual approximation, and no free-text keyword matcher claims semantic equivalence.
- Android, iOS, and macOS model instructions isolate the assertion from untrusted screenshot/context data, prohibit following embedded instructions or proposing tools/actions, and require an inconclusive response when visual evidence or instruction/data separation is uncertain. Only schema-valid evidence-based verdict fields are accepted; a model's own assertion of safety is not external-processing authorization. Controlled adversarial-image verification does not establish a general proof of model prompt-injection immunity.
- Assertion results retain safe explanation/confidence, measured latency/usage, provider identity, capture/region provenance, and references. Approved detailed prompt/output evidence remains Run-local and redacted; operational logs, exceptions, and model-facing tool summaries do not copy credentials, PNG bytes, unrestricted prompt text, or hidden reasoning. Web and Windows assertion semantics are unchanged.
- Suggestion analysis consumes parsed source Case data and bounded completed execution facts. Its prompt prohibits changing completed status/facts or initiating another run; the service cannot invoke UI actions. A missing nullable field is invalid, not an implicit absent candidate. Application owns candidate validation, source preservation, persistence, and publication rules.
- Public evaluation and analysis remain synchronous. Provider adaptation bridges asynchronous invocation with fresh loop-scoped resources and closes on every path. Service reuse does not reuse a closed async client.
- Readiness sends no inference, constructs no harness, and exposes safe verdict/message/action only.

Chinese syntax verification includes the actual Coding Agent Goal containing an immediately adjacent fullwidth parenthetical restriction, matching opening/closing wrappers, post-address explanatory quotation/book-title/bracket forms, ellipsis/em dash, recognized colon labels, Markdown strong emphasis, and combinations with existing explicit wrappers. Negative cases retain malformed-wrapper/continuation rejection and unsafe-prefix rejection; explicitly enclosed URLs containing those same punctuation characters retain exact path/query/fragment text through preparation and shared Execution.

## Verification Scope

Verify strict whole-document validation and required nullable fields through the engine conversion/parser boundary, three-way assertion outcomes with safe category/reason metadata, evidence/timing/usage preservation, suggestion immutability and candidate normalization, and scoped cleanup with primary-error/cancellation precedence. Neutral model-session doubles honor output contracts and return parsed values; they do not depend on production text fallbacks. Actual private service schemas participate in both pinned-client controlled-transport checks. Application integration verifies no candidate publication after invalid analysis and preservation of completed Run/report facts. Factories/readiness and caller imports use this public package without inference, extra actions, or Core/provider dependency cycles.

Quick Test verification distinguishes short sufficient goals, missing or ambiguous application/test intent, explicit versus inferred identity, native identity inference from ordinary application names including continuous Chinese text, malformed/refused/timed-out output, and safe resource cleanup. An inferred identity is not required to occur literally in the prompt; the application reference and any claimed explicit identity still require valid provenance. The actual intent schema participates in the same configured-Provider and controlled-transport contracts without live credentials or UI actions.

Web parser verification covers adjacent Chinese prose punctuation/quotes/brackets, explicit delimiters and Markdown boundaries, balanced path parentheses, IPv6/ports, exact query/fragment/percent-escape and terminal-punctuation preservation, ordered multiple addresses, and rejection of malformed/unsupported, partial, embedded, userinfo, unsafe-character, and ambiguous references. Application-through-shared-Execution tests assert that the original selected reference reaches frozen `harness.web.base_url` unchanged, not merely that intent analysis accepts it. Controlled model replies use the real output schema/provenance checker; parser and preparation tests need no live model, network, or browser.


Web search verification distinguishes a clear discovery goal from a bare topic or an unspecified website test. Classification is not proof that a search occurred or that an answer is correct; actual browser activity and final evidence requirements belong to execution and goal verification.

Effort verification covers configured non-default propagation from each factory into the service's neutral request, compatible direct construction with the mid fallback, invalid-value engine failure without inference, and no-inference readiness. Native serialization is verified through the pinned-client transport checks; output parsing, one-logical-request behavior, and cleanup remain independent of effort.

Explicit-target verification covers exact complete URL validation before inference, punctuation/Unicode/IPv6 preservation, actionless-goal rejection, no dependence on model address echo, no goal-text re-extraction, and no substitution or search fallback when an explicit URL is invalid. Compatibility checks preserve goal-only and address-free Web search plus unchanged native interpretation. The actual Coding Agent goal with an adjacent fullwidth parenthetical restriction is tested through preparation into the shared Execution request, together with incomplete-parenthesis rejection.
