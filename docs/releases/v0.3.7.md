# FSQ v0.3.7 release preparation

Date: 2026-11-21. Python distribution: `fsq-agent` 0.3.7. FSQ remains alpha.
This document prepares a release identity and notes; it does not establish a
`v0.3.7` tag, GitHub release, PyPI publication, or deployed Website revision.

## Changes since the 0.3.6 preparation

- macOS `AppiumConnectMacOSDriver` frontmost attachment, key/app resolution, and
  Mac2 resilience (`d480bd3`): added `bundle_id="auto"` / omitted initial
  frontmost GUI attachment (`frontmost_macos_app` + `lsappinfo` fallback),
  expanded `press_key` desktop alias normalization, added `.app` `app_path` and
  local application name resolution (`resolve_macos_app_bundle` + `open -a`
  unbundled fallback), enabled `TextArea` / `TextView` / `WebArea`
  `enabled=false` tolerance in `type_text`, added `operation_timeout` / idle
  `Session.ensure_alive` lossless session recovery under `skip_app_kill=True`,
  and added frontmost-window subtree fallback plus 28,000-character adaptive
  compaction in `ui_snapshot`.
- macOS same-bundle idempotent `launch_app` and running-app lossless switching:
  `AppiumConnectMacOSDriver.launch_app` short-circuits idempotently when an
  active healthy session is already bound to the resolved target `bundle_id`
  without non-empty `arguments` (regardless of `new_session`), foregrounding via
  `Session.device.activate_app` without tearing down WebDriverAgentMac; when
  creating or switching a Mac2 session for an already-running GUI application
  (`lsappinfo info -only pid <bundle_id>`) without non-empty `arguments`, it
  pre-activates via bounded `/usr/bin/open -b` before
  `create_mac2_session(..., no_reset=True, skip_app_kill=...)` while keeping
  `skip_app_kill=True` by default across session switches and disposal.
- `macos-harness.md` and `MacOSLaunchAppParams` guidance updates: clarified
  avoiding redundant `new_session=true` restarts on already-open target apps or
  documents, cross-bundle Mac2 accessibility-tree rebinding vs
  `new_session=false` foregrounding, native document/script extension
  preservation (`.pages`, `.numbers`, `.key`, `.scpt`) without stripping
  extensions in Finder, standard extensionless Obsidian WikiLinks
  (`[[NoteName]]`), and running saved Automator `.workflow` workflows once when
  execution output is required.
- Python metadata and its exact distribution-contract assertion advance to
  0.3.7, pinned to `appium-connect-agent==0.1.1`. The private npm package
  retains its independent 0.1.0 version.

These changes are established by repository history following `0.3.6`. The
comparison references below anticipate release tags rather than claiming that
`0.3.7` has already been tagged or published.

## Upgrade after publication

Once 0.3.7 is published and obtainable from the package index used by your
Python environment, upgrade with:

```bash
python -m pip install --upgrade fsq-agent==0.3.7
```

Project-local Skills are copies. Package installation or a host reload alone
does not refresh them. From your Coding Agent project, explicitly run:

```bash
fsq init --agent skill
```

Review installer updates, backups, and conflicts under `.agents/skills/fsq/`,
then reload Skill discovery or start a new Coding Agent session.
`--no-overwrite` preserves an existing copy. Existing Android, Web, Windows,
macOS, and iOS Workspaces and Provider configurations require no
reinitialization solely for this version change.

Continue through either [Coding Agent or FSQ UI](../getting-started.md).
Quick Test uses the dedicated user-level Workspace, returns inspectable
results/evidence, and does not save a formal Case or automatically replay one.
Python 3.11+, a configured supported Provider and selected model, and
[platform-specific prerequisites](../platform-prerequisites.md) still apply.
Never paste Provider credentials into Coding Agent chat.

## Validation and publication status

The preparation uses failing exact-version and behavioral contract checks before
production edits, followed by the focused macOS harness, terminal disposal,
config, skills, recording, case-test, and distribution-contract suites, Ruff
lint/format checks, and an independent bidirectional SPEC-implementation audit.
Results belong to the final identified source snapshot and its external
validation evidence; these instructions do not assert a passing result.

Final frontend compilation, wheel and sdist creation, a wheel rebuilt from the
sdist, metadata/resource comparisons, fresh source-free installed-package smoke
tests, and CI matrix verification run in repository automation. Building a local
wheel does not prove public installation availability.

No tag creation, workflow dispatch, GitHub release, PyPI upload, or deployment
is performed by this preparation. Publication requires a separate authorized
release action and its existing manual verification/environment prerequisites.
